# 23 · 远端模型档案与八档阶梯（夜班的执行方式）

这一份定的是"夜班到底用哪个模型、用多强的思考、花多少钱"，全部按**官方文档口径**，
不是我自己试出来的经验值。

## 一、官方口径（我抓的原文，2026-10 版）

| 项目 | deepseek-flash | deepseek-v4-pro |
|---|---|---|
| 实际模型 | DeepSeek-V4.1-Flash-1017 | DeepSeek-V4-Pro-0813 |
| 上下文 | **1M** | **1M** |
| 输出上限 | **384K** | 384K |
| 思考模式 | 支持，**默认开启** | 同 |
| 图像理解 | 支持 | **不支持** |
| 并发（账号级） | 2500 | 500 |

- 只认这两个模型名。传 `deepseek-pro` 会报错；传 `deepseek-chat` / `deepseek-reasoner`
  会被**静默映射成 flash**（返回的 `model` 字段就是 deepseek-flash）。
- 思考参数：`thinking:{type:enabled|disabled}` 与 `reasoning_effort: none|low|high|max`。
  `thinking` 优先；都不传时默认**开思考、强度 high**。别名：`minimal`→low，`medium/xhigh`→high。
- `max_tokens` 范围 1~384K；不设时：非思考 8K、思考 64K、`max` 档 128K。

### 价格（元/百万 tokens）

| | flash 空闲 | flash 高峰 | pro 空闲 | pro 高峰 |
|---|---|---|---|---|
| 输入（缓存**命中**） | 0.02 | 0.04 | 0.15 | 0.30 |
| 输入（缓存未命中） | 1 | 2 | 4.5 | 9.0 |
| 输出 | 4 | 8 | 13.5 | 27.0 |

高峰 = 北京时间**周一至周五 9:00–12:00、14:00–18:00**；其余时段（含周末与法定节假日全天）
都是空闲，**价格减半**。

两个结论直接决定了设计：
1. **缓存命中便宜 50 倍**（flash 0.02 vs 1）。所以提示词必须让"前缀逐字相同"。
2. 思考强度是**按输出价计费**的（`reasoning_tokens` 算在 completion 里），所以档位要省着升。

## 二、八档阶梯（用户指定，默认就按这个递增）

```
第1档 flash:none → 第2档 flash:low → 第3档 flash:high → 第4档 flash:max
→ 第5档 pro:none → 第6档 pro:low → 第7档 pro:high → 第8档 pro:max
```

规则（`core/company.py` + `core/remote.py`）：

| 场景 | 行为 |
|---|---|
| 同一张单失败 | 记一次失败，**没有达到阈值不升档** |
| 连续失败达到阈值（默认 2，可改） | 升一档，失败计数清零（新档重新给机会） |
| 偶发失败（429 限流、超时、5xx） | **不升档**（花更贵的钱解决网络抖动是浪费） |
| 这张单**成功** | **立刻回到第 1 档**，高档次不被后面的单继承 |
| 换一张新单 | 从第 1 档开始（每张单各记各的档位） |

> "解决之后自动回低档"是用户明确问过的点：是的，`tier_reset` 事件会记下来。

## 三、切换模型会不会"重读整段代码、浪费 token"

诚实回答：**我们从来没有把整个仓库发过去**，每次只发
「铁律 + 该模块全文（≤2000 字符）+ 该符号现状 + 工作单与证据」。
但切档确实有成本，涉及三件事：

1. **换模型/换强度 = 换缓存**。DeepSeek 的前缀缓存按模型算，切档后新模型没有这段前缀的缓存，
   这一单的输入要**按未命中全价**再付一次。所以才有"偶发失败不升档""解决即回档"这两条。
2. **提示词顺序决定命中率**。原来【工作单】排在【同文件全文】前面 —— 同一模块的多张单
   一上来前缀就分叉，等于每次全价。现在改成：铁律 → 同文件全文 → 目标符号 → 工作单/证据
   （稳定在前、多变在后，重试只在尾部追加），同模块的多张单因此共享前缀。
3. **同证据去重缓存**：一样的提示词 + 一样的模型 + 一样的档位问第二次，直接复用上次答复，
   **0 token**（`remote_cache`）。

`checks/check_ladder.py` 把这三件事都钉成了断言（含"同文件全文必须在工作单之前"）。

## 四、模型档案（界面上可增删改）

每个档案 = 一条可编辑配置，存在本机 `settings.json` 的 `remote.models`：

```json
{"id": "flash", "model": "deepseek-flash", "priority": 10,
 "efforts": ["none", "low", "high", "max"], "max_output_tokens": 8000,
 "base_url": "", "api_key": "", "enabled": true,
 "pricing": {"offpeak": {"in_hit": 0.02, "in_miss": 1.0, "out": 4.0},
             "peak":    {"in_hit": 0.04, "in_miss": 2.0, "out": 8.0}}}
```

- **priority**：升序决定谁先上（改小 = 优先使用）。界面上的"设为优先"就是把它的值调到最小。
- **efforts**：这个模型要试哪几档思考强度（删掉 `max` 就永远不试 max）。
- **pricing**：空闲/高峰两套价，**用量按这里算钱**。DeepSeek 以后改价、改接口地址、
  加新模型，只改这里，不用改代码。
- 删除档案时至少留一个，否则夜班没有模型可用（接口会直接拒绝）。

接口：`GET/POST /v1/settings/remote/models`、`DELETE /v1/settings/remote/models/{id}`、
`POST /v1/settings/remote/models/primary/{id}`、`GET /v1/settings/remote/usage`。

## 五、用量与花费（界面下方那张表）

- 按 **模型**、按 **思考档位** 两个维度分账；
- 每次调用单独记 `prompt / completion / reasoning / cache_hit / offpeak / cost_cny`；
- 历史记录按**它当时记录的峰谷标记**计价，不会因为"现在几点"被重算；
- 缓存省下的钱单独列出来（命中部分若按未命中价要多花多少）。

## 七、边界（不许含糊）

- 官方只认两个模型名；`deepseek-chat` / `deepseek-reasoner` 会被静默映射成 flash，
  所以界面上写错模型名不会报错，但**实际用的是 flash** —— 价格表按 flash 算才对得上账。
- 我们自己的单次上限仍是 `max_output_tokens=12000`（flash）/`16000`（pro），不是官方 384K：
  单函数代码用不到那么长，设大只会让模型写废话。
- 升档阈值默认 **1** 次（`escalate_after`，可在界面「升档阈值」那一格改，1~9）——
  失败一次就升档、成功了立刻回最低档（11-10 的双向弹性）。
- 切档后新模型那一单的输入确实是全价 —— 这是这套机制的固有成本，
  用"偶发不升档 + 成功即回档 + 前缀稳定"三条把它压到最低。
