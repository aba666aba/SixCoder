# 多智能体软件工程架构：从旧代码里**带走的东西**

旧仓库（`sixagent-server` / `sixagent-web` / `coder-core`）作为**代码**在新架构里用不上，
但有 4 个**接口契约**值得带走，已按下面的形式落到 `prototype/core/`：

| 旧实现 | 有价值的契约 | 新架构里的落点 |
|---|---|---|
| `AgentInteractionService`（按 agentType 下发指令 / 反馈上下文 / 指令历史 / 标记已应用） | "人/上级可以给某个角色下单，下单留痕" | `core/workorder.py`：工作单表（kind/target/symbol/acceptance/status/result） |
| `PipelineLogService`（每步 LLM 调用开始/结束、用户指令、错误） | "每一轮每一步都要可审计" | `remote_usage` + `progress` 表 + 任务事件流（events） |
| `OutputFileService`（按 agentType 分目录产出） | "多候选各写各的，再择优" | 目前用"节点工作区 + 快照"实现，多候选择优待接（Best-of-N 已有选择器） |
| `OrchestratorService` / `ReviewerService` | "总控负责拆活，评审负责判对错" | `core/iterate.py`（总控=分诊+循环）、`core/handoff.py`（评审=远端出方案 + 本地闸门验收） |

## 新架构（目标态）

```
需求
 └─ 架构师（远端大模型）        ← 只看证据：体检结果 + 契约 + 失败判据
     ├─ 根因（一句话）
     └─ 工作单 ×N（每单 <5，可机械验收）
         └─ 执行者（本地小模型）  ← 一次只做一张单，只改一个符号（libcst 保真渲染）
             └─ 机械验收（契约判据/闸门）→ 记账（progress）
                 └─ 未通过 → 结果回传架构师 → 下一轮
```

## 旧代码为什么用不上（结论）

| 旧资产 | 结论 | 原因 |
|---|---|---|
| `sixagent-server`（Spring Boot，36 MB） | **删除** | 与本项目 Python/FastAPI 技术栈不同；有价值的只有上表 4 个契约，已用 Python 重写 |
| `sixagent-web`（旧 Electron 前端，1.26 GB） | **删除** | 现用 `prototype/web` + `shell/` 替代，功能覆盖更全（含远端设置/用量/回归库） |
| `coder-core`（RAG+ReAct，5.7 MB，490 测试） | **删除** | 它的检索思路已被符号级索引方案超越（万级实测见 `18-仓库规模与符号图实测.md`：10,224 文件建库 71.5 s、查询 0.02 ms）；其测试体系针对另一个产品 |

> 设计要点没有丢：上面表格已把它们固化成**文档 + 已实现的模块**，代码本体不再需要。
