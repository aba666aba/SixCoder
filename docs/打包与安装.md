# 打包与安装（Windows 安装包 / NSIS）

> 打包是独立主题，不属于开发文档（唯一事实来源）的范围。
> **2026-11-20 重写**：用户入口收敛成一个 EXE，根目录的 bat/ps1 全部删除，打包脚本也从
> PowerShell 收成 Python。旧版（2026-11-05，1.0.0）的流程留在文末"历史附录"，仅作存档。

## 10.0 一句话

双击 `SixCoder-Setup-<版本>.exe` 即装即用：**用户不需要装 Python、不需要装 Node**（包内自带
便携 Python 3.12 + 全部运行依赖 + 后端源码 + 前端产物）；**装新版本直接再双击一次**（覆盖安装，
本地数据保留）；卸载走「设置 → 应用」，卸载页可选**是否保留本地运行数据**（默认保留），
**你的项目仓库永远不在删除范围内**。

## 10.1 产物与命令

| 项 | 值 |
|---|---|
| 安装包 | `dist-installer\SixCoder-Setup-<版本>.exe`（1.1.0 实测 **195.4 MB**，x64，NSIS） |
| 构建产物目录 | `dist-installer\release-<时间戳>\`（每次构建一个新目录，见 §10.8 坑 2） |
| 安装位置 | 固定 `%LOCALAPPDATA%\Programs\SixCoder`（**per-user，不弹管理员，不允许改目录**） |
| 运行期数据 | `%LOCALAPPDATA%\SixCoder`（日志/数据库/密钥；与安装目录分离，见 §10.3） |
| 卸载入口 | Windows「设置 → 应用 → SixCoder → 卸载」 |
| 出包命令 | `python packaging\build_installer.py` |
| 卸载验证 | `python packaging\test_uninstall.py --yes`（会真装真卸，跑前确认夜班已停） |

参数：`--skip-ui`（复用已有前端 dist）、`--skip-deps`（跳过依赖安装）、`--regen-icon`
（重新生成图标，需宿主 Python 有 Pillow）、`--prune`（删内置 Python 的字节码缓存）。

## 10.2 构建脚本做了什么（`packaging/build_installer.py`，可重复执行）

1. **前端**：`npm ci`（首次）+ `npm run build` → `prototype/web/dist`；
2. **便携 Python**：没有就下载 `python-3.12.10-embed-amd64.zip` → 解包到 `shell/resources/python`
   → 打开 `_pth` 里的 `import site` 并追加 `Lib\site-packages`；
3. **pip 引导**：下载 `get-pip.py` 装进这套便携 Python；
4. **运行依赖**：`pip install -r prototype/requirements.txt`（默认走清华镜像，
   `SIXCODER_PIP_INDEX` 可覆盖），装完**真 import 一遍**（`import` 失败直接 fail，不出成品）；
5. **图标**：默认复用 `shell/build/icon.ico`；
6. **打包**：`npx electron-builder --config ..\packaging\electron-builder.json --win nsis --x64`，
   并尝试 `-c.electronDist=node_modules/electron/dist` 跳过"解压+改名"（见 §10.8 坑 3）；
7. **交付**：成品复制到 `dist-installer\SixCoder-Setup-<版本>.exe`（固定路径）。

打包内容（`extraResources`）：`resources/python`（便携解释器）、`resources/prototype`
（后端源码；过滤 `__pycache__`/`*.pyc`/`.tmp*`/`.sixcoder`/`*.db`/`web/node_modules`/`demo-repo`/
`workspaces`/`_logs`/`checks`/`docs`）。

## 10.3 数据目录分离（"卸载不残留 / 可选保留"的地基）

`prototype/core/paths.py` 统一决定运行期数据往哪写：

| 场景 | 数据根 | 说明 |
|---|---|---|
| 开发态（无环境变量） | 仓库根 | 与历史行为完全一致，零迁移 |
| 安装版 | `%LOCALAPPDATA%\SixCoder` | `shell/main.cjs` 设 `SIXCODER_HOME` 传给后端 |

受它管辖的写入点：`core/db.py`（sqlite）、`core/runtime_cfg.py`（engine.json）、
`core/company.py`（night-*.json）、`tools/watchdog_night.py`（watchdog.log/pid）、
`tools/patrol.py`（patrol.log）、`server.py`（夜班/运维任务日志）。

**为什么必须这么做**：只要还有运行期写入散在安装目录里，"卸载时保留历史"就只能靠卸载器
逐个目录挑着删——一定会漏；而且装到只读目录直接崩。收敛到一个目录后语义变干净：
删程序本体 + 删这个目录 = 彻底无残留；只删程序本体 = 数据留着，重装接着用。

> 产物仓里的 `.sixcoder/`、`_logs/` 属于**用户的项目**，永远跟随 `--repo`，不进这里。

## 10.4 覆盖安装（更新路径）

- **同一个 appId + 固定安装目录** → 双击新安装包即覆盖，不产生第二份安装。
- `customInit`（`installer.nsh`）检测 `$INSTDIR\SixCoder.exe` 是否存在 → 判定"更新"，
  可选组件页标题改成「覆盖更新（本地数据会保留）」。
- `customInstall` 先清三类会占文件的进程：`SixCoder.exe`、$INSTDIR 下**所有**进程
  （含它拉起的后端）、脱离运行的夜班。不清就会踩 electron-builder 的原子替换失败
  （整目录改名 → 一个句柄就中止）。
- **数据不受影响**：数据在 `%LOCALAPPDATA%\SixCoder`，不在 `$INSTDIR` 里。
- 装完界面需要重新打开；夜班若之前被停，回界面点一次「开始夜班」。

## 10.5 卸载：勾选框 + 清理清单

卸载页（`customUnWelcomePage`）只有一个勾选框，**默认勾选**：

> 保留本地运行数据（夜班日志、任务历史、已保存的远端密钥）

| 选择 | 删什么 |
|---|---|
| 勾选（默认） | 程序本体（`$INSTDIR`）、Electron 缓存/会话、快捷方式、注册表、开机自启；**数据目录保留** |
| 不勾 | 以上 + `%LOCALAPPDATA%\SixCoder` 整目录（彻底无残留） |

- **静默卸载 `/S`** 不显示页面 → 走"保留"分支（宁可留数据，不误删）；要静默全清必须显式
  加 `/WIPEDATA`（自动化测试用）。
- **用户项目仓库不在任何删除语句里** —— 安装目录之外，卸载脚本连它的路径都不出现
  （`check_packaging.py` 有一条静态断言钉住这一点）。

被清的位置（`shell/build/installer.nsh` + electron-builder 自带逻辑）：

| # | 位置 | 说明 |
|---|---|---|
| 1 | `%LOCALAPPDATA%\Programs\SixCoder` | 安装目录（含内置 Python 与后端） |
| 2 | `%APPDATA%\SixCoder` / `%APPDATA%\sixcoder-shell` | Electron userData / 会话 |
| 3 | `%LOCALAPPDATA%\sixcoder-shell`、`%LOCALAPPDATA%\SixCoder\Cache|GPUCache` | 缓存 |
| 4 | 桌面 / 开始菜单 / 「环境准备」快捷方式 | 3 个 lnk |
| 5 | 任务栏固定项 | 按 AppUserModelId 缓存 |
| 6 | `HKCU\Software\Classes\AppUserModelId\com.sixcoder.desktop` | 任务栏图标标识 |
| 7 | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\SixCoder` | 开机自启 |
| 8 | 运行中进程 | `SixCoder.exe` + **仅限 $INSTDIR 下**的 python（绝不 `taskkill /IM python.exe`） |
| 9 | 控制面板卸载项 | electron-builder 自行注销，不留空壳 |

## 10.6 端到端验证

`packaging/test_uninstall.py --yes`：静默安装 → 植入用户数据 → 静默卸载（保留分支）
→ 逐项查残留 → 再装 → `/WIPEDATA` 卸载 → 查彻底清空。

静态那半边在 `prototype/checks/check_packaging.py`（41 条断言）：旧脚本已删、安装包结构、
可选组件默认不勾、卸载勾选框默认保留、静默 `/WIPEDATA`、不碰用户仓库、内置解释器能 import。

**1.1.0 实测**（2026-11-20）：全新目录静默安装 **rc=0 / 540.9 MB / python.exe + server.py 齐全**；
安装耗时约 2 分 15 秒。

## 10.7 环境准备（Ollama / 模型）走 EXE 参数，不再有 ps1

```
SixCoder.exe --env-setup --ollama            # 只装 Ollama
SixCoder.exe --env-setup --model             # 拉默认模型（缺 Ollama 会先装）
SixCoder.exe --env-setup --ollama --model    # 两个都要
```

实现：`shell/main.cjs` 识别 `--env-setup` → 开一个新控制台窗口跑
`prototype/tools/env_setup.py`，主进程立即退出。逻辑只有一份（Python），
`--dry-run` 供自检。原来的 `packaging/assets/env-setup.ps1` 已删除。

- 安装器勾选框（默认都不勾）→ `customInstall` 拼参数调上面这条命令；
- 随时可补装：开始菜单 `SixCoder 环境准备`（同一条命令）。

## 10.8 这轮踩的坑（别再重犯）

| 坑 | 现象 | 结论 |
|---|---|---|
| **Git Bash 把 `/S` 当路径** | 安装器走成 GUI 交互模式、目录装一半、缺 `resources/python`，rc=1 | 在 Git Bash 里跑带 `/S`、`/D=` 的命令会被 MSYS 路径转换改写；**用 PowerShell `Start-Process -ArgumentList '/S'`**，或 `MSYS_NO_PATHCONV=1` |
| **electron-builder 复用 output 目录** | `[safe-delete] BULK_CONFIRM_REQUIRED` / `EPERM rename win-unpacked.tmp`，构建中途失败 | 受管环境里批量删除会被拦；每次构建落到 `release-<时间戳>` 新目录，成品再复制回固定路径（`-c.directories.output`） |
| **`moveDirAtomic` 也会被拦** | 报 "Failed to move directory ... win-unpacked.tmp" | 同上；脚本会尝试 `-c.electronDist=node_modules/electron/dist` 直接复用已解压 Electron，跳过解压+改名 |
| **覆盖安装被旧进程占用** | 安装成功但目录只剩 0.4 MB（旧文件删了、新文件没落） | `customInstall` 必须先把 `$INSTDIR` 下所有进程清掉（不只 `SixCoder.exe`） |
| **`.ps1` 里写中文注释** | PowerShell 5.1 按 GBK 读 → 解析失败 | 打包脚本已改 Python，此坑作废；其它 ps1 一律纯 ASCII |
| **Node 不信任本机证书链** | `unable to verify the first certificate` | 构建时 `NODE_OPTIONS=--use-system-ca`（脚本已设） |
| **dist 存在就跳过前端构建** | 旧产物被打进安装包（窗口标题还是"原型"） | 默认**每次强制重建**；`--skip-ui` 是显式的、有警告 |
| **NSIS 卸载器会自我复制** | 原进程立即 exit 0，卸载在 `Un_A.exe` 里继续 | 判断"卸载完成"看目标状态（目录消失 + 无进程），别只看进程名 |

### NSIS 的三个老坑（1.0.0 时踩的，仍然适用）

| 坑 | 现象 | 结论 |
|---|---|---|
| **自定义 include 被插在模板最前面** | `${MUI_*}` 未定义 → 编译失败 | 不能用 MUI 宏；标题自己用 `${NSD_CreateLabel}` + `CreateFont` + `WM_SETFONT` 画 |
| **同一份 include 也参与卸载器构建** | warning 6010/6001，而 makensis `-WX` 把警告当错误 | 安装期代码（含 `Var`）包进 `!ifndef BUILD_UNINSTALLER`，卸载期包进 `!ifdef BUILD_UNINSTALLER` |
| **`nsDialogs.nsh` 重复 include** | — | 它自带 include guard，自己 include 一次是安全的（顺带引入 LogicLib/WinMessages） |

## 10.9 程序图标：`<6>` 锁定组合（2026-11-05 定稿，仍有效）

### 需求

> 用户要求：想办法生成一个有设计感、同时含"6"和"代码"元素的程序图标。

之前 `shell\build\icon.ico` 是脚本画的深蓝方块占位图。这一版把它换成真正设计过的标。

### 设计拆解（为什么长这样）

| 元素 | 具体做法 | 作用 |
|---|---|---|
| 底 | 深靛蓝圆角方块（半径 22.5%），135° 渐变 `#1B2559 → #070A17` | 现代 IDE 深色底，满血到边（VS Code / Slack 那种） |
| 光 | 中部青色径向辉光（`#38BDF8`，峰值 α66）+ 四边暗角 | 视线被压回中间，图标在任务栏上不"糊成一块" |
| 代码纹理 | 上下各两行极淡圆角短线（白色 α20–34，其中一小段是青色 α34，模拟语法高亮） | 放大（≥96px）时给出"代码编辑器"的暗示；小尺寸直接不画 |
| 主体 | 大号数字 6，上白下淡蓝渐变（`#FFFFFF → #B7C7FF`） | 产品名 SixCoder 的"6"，视觉中心 |
| 字体 | Consolas Bold | Visual Studio 的默认代码字体 —— "代码"语义来自字体本身，不靠贴图 |
| 代码元素 | 两侧圆头、等粗的尖括号 `<` `>`，青色渐变（`#6EE7F9 → #22B8F0`） | 和 6 组成 **`<6>`** 标签，一眼看出是命令行/代码 |
| 细节 | 投影（下移 1.2%、模糊 2%、α42）+ 1px 内高光边 | 让白字从辉光里浮起来，有玻璃边的高级感 |

层级：**6 是主角（白、最大），尖括号是配角（青、更细）**。
16px 下尖括号退化成一左一右两个小色块，不抢戏；这也是为什么小尺寸敢直接砍掉它们（见下）。

### 小尺寸简化版（关键工程决定）

| 尺寸 | 画法 |
|---|---|
| 16 / 20 / 24 px | **只画 6**（墨迹高占 62%），不画尖括号 |
| 32 px 以上 | 完整 `<6>` 锁定组合 |

理由：实测 `<6>` 在 24px 以下会糊成三个色块，谁也认不出。小尺寸的规矩是"一个元素、越粗越好"，
这也是各家图标的常规做法（小尺寸不是等比缩小，是另画一版）。

另一个细节：**光学居中**。6 的墨迹天生偏左（开口在右上），严格居中看着偏左，
所以整个锁定组合右移 0.6%×边长。

### 生成方式（可复现，不塞二进制进仓库）

```powershell
python -m pip install -r packaging\requirements-build.txt   # 只有构建机需要 Pillow
python packaging\make_icon.py            # 生成 + 打印自检 + 字符画预览
python packaging\make_icon.py --no-preview
```

- 每个尺寸**单独**从超采样画：16/20/24 用 16×、≤64 用 8×、≤128 用 4×、256 用 2×，
  再 LANCZOS 缩到目标尺寸。**绝不拿 256 硬缩到 16**（那样 16px 必糊）。
- 产物：
  - `shell\build\icon.ico` —— 9 帧：16/20/24/32/40/48/64/128/256，381 KB
  - `packaging\assets\icon-preview.png`（512 预览）、`icon-sizes.png`（各尺寸排排站）
- 想换真实 logo：同名覆盖 `shell\build\icon.ico`，打包时加 `-KeepIcon` 跳过生成。

### 验证：两层证明，都不靠"我觉得好看"

`packaging\verify_icon.ps1` 干两件事：

1. **GDI+ 真解码**：用 `System.Drawing.Icon` 逐尺寸解码 → `ToBitmap()` → 数白色墨迹与青色墨迹
   的像素比例，任何一个尺寸丢了 6 或丢了尖括号就 FAIL。
2. **Shell 探针**：`PrivateExtractIcons`（Explorer 自己用的 API）问 16/32/48/64/256，
   每个都必须返回**原生**尺寸，否则说明 Shell 在偷偷缩放邻近帧。

实测（2026-11-05）：

```
  16px -> decoded  16x 16  white= 7.81%  cyan= 3.12%  ok     (简化版)
  24px -> decoded  24x 24  white=10.07%  cyan= 1.04%  ok     (简化版)
  32px -> decoded  32x 32  white= 6.25%  cyan= 6.74%  ok
  48px -> decoded  48x 48  white= 6.73%  cyan= 5.73%  ok
  64px -> decoded  64x 64  white= 7.37%  cyan= 5.81%  ok
 128px -> decoded 128x128  white=  8.2%  cyan= 6.35%  ok
 256px -> decoded 128x128  <- GDI+ 的上限，不是图标坏了（见坑 2）
shell probe: asked 16/32/48/64/256 -> got 16/32/48/64/256  全部原生
```

另外 `make_icon.py` 自己还会回读 ICO 目录并逐个尺寸打印不透明度/白色墨迹/青色墨迹比例，
任何一档丢掉主体就 `SystemExit`（构建脚本因此会直接失败）。

### 这一节踩的 4 个坑

| 坑 | 现象 | 结论 |
|---|---|---|
| **PNG 帧** | 128px 用 PNG 帧时 `System.Drawing.Icon` 能构造，但 `ToBitmap()` 抛 `Requested range extends past the end of the array` | rcedit / 老 NSIS 对 PNG 帧支持也不齐 → **全部帧写成 DIB(BMP)**，代价只是 99 KB → 381 KB（相对 139 MB 的安装包不值一提） |
| **GDI+ 不支持 256** | 问 256 回 128×128，看着像图标做坏了 | 这是 .NET 的限制；要证明 256 是真帧只能用 `PrivateExtractIcons` + `GetObject` 读回位图宽度 |
| **构建脚本用错了 Python** | 第 5 步原来用**捆绑的嵌入版 Python** 跑 `make_icon.py`，而它没有 Pillow → 打包直接失败 | 改成在宿主找 `python`/`py` 探测 `import PIL`；**不要**往嵌入版里装 Pillow（那是要进安装包的运行时） |
| **ICO 目录项字段偏移写错** | 回读校验报 `frame is not 32bpp` | ICO 目录项里 `bitCount` 在偏移 **6**（planes 在 4），不是 10；自检脚本第一时间抓住了这个错 |

### 定稿（2026-11-05，用户确认"就用它"）

这版图标就是正式图标，不再迭代。给后来的人留三个数：

| 项 | 值 |
|---|---|
| 产物 | `shell\build\icon.ico`：9 帧（16/20/24/32/40/48/64/128/256），372 KB |
| SHA256 | `8B82724DD300E349222E10A039B965135A109F7776D91663D739CDB522DCB075` |
| 生成参数 | `python packaging\make_icon.py --no-preview`（全默认，不加任何参数） |

**为什么要记 SHA256**：同一份脚本重跑必须字节一致（已实测），所以这个 hash 可以当"图标有没有被换过"的指纹。
哪天发现 hash 变了，说明有人换了图标或改了脚本参数 —— 要么是有意换，要么是不小心改了
`_lockup()` 的比例常量，两种情况都该在那次提交/记录里说清楚。

已内嵌并验证：`dist-installer\win-unpacked\SixCoder.exe` 与 `dist-installer\SixCoder-Setup-1.0.0.exe`
（16/32/48/64/256 全部原生解析）。

### 还没做的（诚实标注）

- 图标仍是"用脚本画出来的设计稿"，不是专业设计师的矢量源文件；真要品牌化建议出 SVG/AI 源稿
  再导出（同名覆盖 + `-KeepIcon` 即可）。
- 只做了 Windows（ICO）。macOS 的 `.icns`、Linux 的 PNG 套图都没做。
- Web UI 没有配 favicon（`prototype/web/public` 里没有图标文件）；要的话可以从同一份
  `icon-preview.png` 生成。

## 历史附录：1.0.0 版流程实录（已被 §10.0–10.8 取代）

## 10.0 一句话

双击 `SixCoder-Setup-1.0.0.exe` 即装即用：**用户不需要装 Python**（包内自带便携式
Python 3.12.10 + 全部运行依赖 + 后端源码 + 前端产物）；卸载走「设置 → 应用」，
**实测 8 项残留检查全清**（含本地 API Key）。

## 10.1 产物与命令

| 项 | 值 |
|---|---|
| 安装包 | `dist-installer\SixCoder-Setup-1.0.0.exe`（约 **138.7 MB**，x64，NSIS） |
| 安装位置 | 默认 `%LOCALAPPDATA%\Programs\SixCoder`（**per-user，不弹管理员**，可自选目录） |
| 卸载入口 | Windows「设置 → 应用 → SixCoder → 卸载」 |
| 出包命令 | `powershell -ExecutionPolicy Bypass -File packaging\build_installer.ps1` |
| 卸载验证 | `powershell -ExecutionPolicy Bypass -File packaging\test_uninstall.ps1` |

## 10.2 构建脚本做了什么（7 步，可重复执行）

1. **前端**：`npm ci` + `npm run build`（**每次强制重建**，见 §10.5 的坑）；
2. **便携 Python**：下载 `python-3.12.10-embed-amd64.zip` → 解包到 `shell/resources/python`
   → 打开 `_pth` 里的 `import site` 并追加 `Lib\site-packages`；
3. **pip 引导**：下载 `get-pip.py` 装进这套便携 Python；
4. **运行依赖**：`pip install -r prototype/requirements.txt`，并**真 import 一遍**验证；
5. **图标**：`packaging/make_icon.py` 生成占位 `shell/build/icon.ico`（256×256，纯 stdlib）；
6. **打包**：`npx electron-builder --config ..\packaging\electron-builder.json --win nsis --x64`；
7. **报告**：打印安装包路径与体积。

打包内容（`extraResources`）：`resources/python`（便携解释器）、`resources/prototype`
（后端源码；过滤掉 `__pycache__`/`*.pyc`/`.tmp`/`.sixcoder`/`*.db`/`web/node_modules`/`demo-repo`）。

## 10.3 卸载彻底：清单与做法

实测被清理的 8 项（`test_uninstall.ps1` 逐项断言）：

| # | 位置 | 说明 |
|---|---|---|
| 1 | `%LOCALAPPDATA%\Programs\SixCoder` | 安装目录（含后端与便携 Python） |
| 2 | `%APPDATA%\SixCoder` | electron userData；**`settings.json` 里的本地 API Key 在这里** |
| 3 | `%LOCALAPPDATA%\SixCoder` | 缓存 / 崩溃转储 |
| 4 | 桌面快捷方式 | `SixCoder.lnk` |
| 5 | 开始菜单快捷方式 | 同上 |
| 6 | 控制面板卸载项注册表 | 不留空壳条目 |
| 7 | `AppUserModelId`（`com.sixcoder.desktop`） | 任务栏图标/通知按它缓存 |
| 8 | 运行中进程 | `SixCoder.exe` 与**包内** `python.exe` |

卸载脚本（`shell/build/installer.nsh`，`customUnInstall`）专门处理三件容易漏的事：

- **杀进程要收窄范围**：先 `taskkill /F /T /IM SixCoder.exe`；再只杀
  "`ExecutablePath` 落在 `$INSTDIR` 下"的 `python.exe`（**不能**直接
  `taskkill /IM python.exe`，会误伤用户自己的 Python 进程）；
- **先删运行期目录再让 NSIS 删安装目录**：`resources\prototype\data`（sqlite）与
  `.sixcoder`（审计留痕）里有文件锁，NSIS 直接删会留残骸；
- **补删两处常被忽略的痕迹**：任务栏固定项
  `%APPDATA%\Microsoft\Internet Explorer\Quick Launch\User Pinned\TaskBar\SixCoder.lnk`
  与 `HKCU\Software\Classes\AppUserModelId\com.sixcoder.desktop`。

## 10.5 这轮踩过的 5 个坑（别再重犯）

| 坑 | 现象 | 结论 |
|---|---|---|
| **`.ps1` 里写中文注释** | PowerShell 5.1 按 GBK 读，直接 `Unexpected token '}'` 解析失败 | packaging 下的 `.ps1` **必须纯 ASCII**；写完用 `[Parser]::ParseFile` 自检解析错误数 |
| **Node 不信任本机证书链** | electron-builder 报 `unable to verify the first certificate`，拉不到 nsis 工具 | 构建时设 `NODE_OPTIONS=--use-system-ca`；脚本内已设 |
| **dist 存在就跳过前端构建** | 旧产物被打进安装包 → **窗口标题还写着"原型"** | 改成**每次强制重建**（Vite 增量 ~0.9s），并打印 `dist title:` 供核对 |
| **NSIS 卸载器会自我复制** | 原始进程立即退出（exit 0），卸载却在 `Un_A.exe` 里继续跑 | 判断"卸载完成"要看**目标状态**（安装目录消失 + 无相关进程），别只看进程名；实测耗时约 16 秒 |
| **测试脚本不可重复执行** | 上一轮中断留下已安装状态 → 下一轮基线就脏 | 测试开头先检测并卸载旧安装 |

## 10.7 已知限制 / 待办

- **没有代码签名**：Windows 会弹 SmartScreen「未知发布者」，需要用户点"仍要运行"。
  正式发版建议买签名证书（OV/EV），并在 `electron-builder.json` 里配 `win.certificateFile`。
- **图标曾有占位图**：早期 `shell\build\icon.ico` 是脚本画的深蓝方块，已换成正式设计稿
  `<6>`（见 §10.9）。要换真实 logo 就同名覆盖 `shell\build\icon.ico`，打包时加 `-KeepIcon`
  跳过生成。
- **只出 x64 / 只出 NSIS**；未做 MSI、未做 arm64。
- **没有自动更新**（electron-updater）；目前靠重新下载安装包覆盖升级。
- **Ollama 不捆**（独立程序、体积大、许可独立）：安装包里不含它，缺了就靠 `python cli.py doctor`
  和 UI 提示引导用户去 ollama.com 装。**这一点必须在对外说明里写清**，否则用户会以为装完就能用。
- **打包机依赖**：出包机需要 Node（electron-builder）、能访问 npm/python.org；
  产物约 139 MB，其中便携 Python 与依赖占了绝大部分。
- 升级安装（覆盖装）走的是 `customInstall` 里的先杀进程；**跨大版本的用户数据保留策略未设计**
  （目前卸载才清数据，覆盖安装保留）。

## 10.8 安装向导可选组件页：两个独立勾选框（2026-11-05 追加）

### 需求与结论

> 用户要求：安装过程中能勾选"装 Ollama"和"拉取默认模型"，**两个可以单独勾选**。

做法：在"选目录"页之后插入一个自定义页（NSIS `customPageAfterChangeDir` 钩子），
两个 `nsDialogs` 复选框，互不影响：

| 勾选项 | 动作 | 体积 |
|---|---|---|
| `安装 Ollama 运行环境` | 下载官方 `OllamaSetup.exe` → Inno 静默安装（`/VERYSILENT /NORESTART /SP-`） | 约 1.1 GB |
| `拉取默认模型 qwen2.5-coder:7b` | `ollama pull`（没装 Ollama 就先自动装一遍再拉） | 约 4.7 GB |

关键取舍：**两个下载都不在安装器进程里阻塞执行**。安装结束时用一个独立控制台窗口跑
`resources\setup\env-setup.ps1 -Ollama -Model`（按勾选拼参数），安装器立刻收尾；
进度与结果写进 `%LOCALAPPDATA%\SixCoder\env-setup.log`。
理由：4.7 GB 的模型下载如果塞进安装器，用户会看到"安装卡死几十分钟"，断网还留半装状态。

- **默认值**：检测到已装 Ollama → 该项变成"Ollama 已安装（勾选则重新运行安装程序）"且默认不勾；
  未装则默认勾上。模型项**默认不勾**（4.7 GB 不该替用户决定）。
- **静默安装（/S）**：页面不显示 → 两个变量为空 → 什么都不做，**绝不偷偷下载**
  （实测确认：静默安装后没有生成 `env-setup.log`）。
- **可重跑**：安装时会在开始菜单建一个 `SixCoder 环境准备` 快捷方式，指向同一个脚本，
  随时可以补装；卸载时一并删除。

### 涉及的三个文件（都在本地、不进 GitHub）

| 文件 | 作用 |
|---|---|
| `shell/build/installer.nsh` | 自定义页 + `customInstall` 拼参数启动脚本 + 卸载清理 |
| `packaging/assets/env-setup.ps1` | 真正干活：检测 →（装 Ollama）→（拉模型）→ 写日志；支持 `-DryRun` 自测 |
| `packaging/electron-builder.json` | `extraResources` 把脚本捆到 `resources/setup/env-setup.ps1` |

### 验证方式（不用截图也能证明页面存在）

模型不支持读图，所以用 **Win32 控件枚举**证明：启动安装器 → 给"下一步"按钮发 `BM_CLICK`
逐页前进 → 用 `EnumChildWindows` + `GetWindowTextW` 读出每个子控件文本。实测输出（本机已装 Ollama）：

```

    [Static] SixCoder 需要一个本地模型（远端主力写代码时，本地当手脚、省 token）。现在一起装好最省事……
    [Button] Ollama 已安装（勾选则重新运行安装程序）
    [Button] 拉取默认模型 qwen2.5-coder:7b（约 4.7 GB）
    [Static] 说明：安装结束后会弹出独立窗口执行下载与安装（不阻塞安装程序）……

```

其它实测：静默安装 → 目录/脚本/两个快捷方式齐全（快捷方式目标为
`powershell.exe -NoProfile -ExecutionPolicy Bypass -File "...\resources\setup\env-setup.ps1"`）；
卸载后安装目录、两个快捷方式、`%APPDATA%\SixCoder` 全部清空。
`env-setup.ps1 -DryRun` 干跑：正确识别已装 Ollama + 服务在线，并列出"将执行 ollama pull"。

### 这一节踩的 3 个 NSIS 坑（务必记住）

| 坑 | 现象 | 结论 |
|---|---|---|
| **自定义 include 被插在模板最前面** | `!include: error in script ... line 32`，因为 `!insertmacro MUI_HEADER_TEXT` 此时还没定义 | 自定义 include 里**不能用 `${MUI_*}` 宏**；标题自己用 `${NSD_CreateLabel}` + `CreateFont` + `WM_SETFONT` 画 |
| **同一份 include 也参与卸载器构建** | `warning 6010/6001`（函数/变量未被引用），而 makensis 用 `-WX` 把警告当错误 | 安装期代码（含 `Var` 声明）全部包进 `!ifndef BUILD_UNINSTALLER` … `!endif` |
| **`.ps1` 里的中文匹配串** | 脚本按 GBK 读 → `'下一步'` 之类的匹配永远失败 | 带中文的 `.ps1` 存成 **UTF-8 with BOM**，或整份保持纯 ASCII（`env-setup.ps1` 是纯 ASCII） |

补充：`nsDialogs.nsh` 自带 `!ifndef NSDIALOGS_INCLUDED` 守卫，所以自己 `!include` 一次是安全的
（顺带引入 LogicLib / WinMessages），不必依赖模板的 include 顺序。

### 还没验证的部分（诚实标注）

- **1.1 GB / 4.7 GB 的真实下载没有在本轮跑通**：本机已装 Ollama 且模型已存在，只验证了
  "检测 → 已装则跳过 → 生成正确命令"这条路径。真下载需要一台干净机器（或用 `-DryRun` 只看计划）。
- Ollama 静默安装参数（`/VERYSILENT /NORESTART /SP-`）是按 Inno Setup 惯例写的，
  需要在干净机器上确认一次。

## 11. 启动可靠性与安装向导（2026-11-20，实测）

### 11.1 "双击打开全蓝、没按钮、提示后端启动失败"

**根因不是 Ollama**（`core/ollama.py` 的 `alive()/models()` 都吞异常，没 Ollama 时
`health` 照样秒回）——是**端口探测只测 TCP 通不通**：别的程序占了 8760，外壳
`waitForPort` 也判"就绪"，于是加载出别人的页面 = 全蓝无按钮。旧错误页还把
"先查 Ollama"写成第一条，纯误导。

修法（`shell/main.cjs`）：
- **真健康检查** `probeHealth()`：HTTP GET `/v1/health`，校验 `app === 'sixcoder'`；
  服务端 `health()` 加 `"app": "sixcoder"` 标识。**三态** `ours | foreign | off`，
  只有 `ours` 才算后端就绪，占端口的冒牌服务判 `foreign` 一律不认。
- **端口自适应** `choosePort()`：8760 上若已是本软件后端则复用；被占则从 8760 起
  逐端口 TCP 探测，找第一个空闲端口起后端（最多 20 个），`PORT` 从 const 改 let。
- **日志落盘**：后端 stdout/stderr 写 `%LOCALAPPDATA%\SixCoder\_logs\backend-shell.log`，
  远程机器出问题能拿到真实原因（原来只在内存里，窗口一关就没）。
- 错误页去掉 Ollama 误导，改为显示退出码/跳过端口/日志路径 + 「重试启动」按钮。

### 11.2 安装向导页面顺序（许可勾选与全文合一）

原来有 4 页挤在一起且顺序乱：许可全文(RTF) → **为谁安装** → **选目录** → 我另起的
"我已同意"勾选页 → 组件页。用户口径："同意的页面和同意许可的勾选框合成一页"。

修法（`shell/build/installer.nsh`）：
- 删掉独立的 `SixCoderTermsCreate/Leave` 页，改用 MUI 原生
  `!define MUI_LICENSEPAGE_CHECKBOX`（放在 include 最顶部、MUI2 展开前才生效），
  许可全文页自带"我已阅读并同意"勾选框，不勾不能下一步——**两页合一**。
- `customInstallMode` 里 `StrCpy $isForceCurrentInstall "1"` 跳过"为谁安装"页
  （per-user 安装本就不需要，它夹在许可和目录之间打断流程）。
- `allowToChangeInstallationDirectory: true` 开放自选安装目录。

### 11.3 实测（安装包 195.4 MB，1.1.0）

- 静默覆盖安装 rc=0 → 安装目录 4687 文件完整（此前中断安装只剩 1 文件是历史坑）。
- 启动安装版 EXE（等价双击）：日志显示"端口选择 8760 / 复用=false"，后端自动起来，
  `/v1/health` 返回 `app=sixcoder`、内置 Python 3.12.10、界面 `/` 返回 200 带 `#app`。
- 端口被冒牌服务占用时 `probeHealth` 判 `foreign`（非 ours），触发 +1 换端口，不再全蓝。
- Ollama 未参与任何启动判定。

### 11.4 安装末期进度条跳动 + 可选组件文案（2026-11-20 下午）

**进度条跳动的根因**：`customInstall` 宏在 `installApplicationFiles`（文件复制，进度条
0→100%）**之后**执行，里面却有两次长 `Sleep`（1.2s + 0.8s，让满格进度条卡住）+ 4 处
`nsExec` + `cmd /c start` 弹控制台黑框盖在窗口上 —— 视觉上就是"跳来跳去"。

修法（`shell/build/installer.nsh`）：
- `nsExec::ExecToLog`（同步等待命令结束，taskkill /F 返回时进程已死）后面的
  两次 `Sleep` **直接删除**，不留卡顿。
- 后台下载/环境准备的启动从 `cmd /c start "标题" "exe" args` 改为 NSIS 原生
  `Exec '"$INSTDIR\SixCoder.exe" --install-runtime ...'`：异步不阻塞、**不弹 cmd 黑框**。
- 卸载期的 `Sleep` 保留（卸载器没有进度条，且要等进程释放句柄才能删净，是两回事）。

**Ollama 描述迷糊**：可选组件页原文案绕弯（"不勾=用你自己装好的环境""不装照样跑，
装了多一层离线能力"）。用户口径："你这些描述就是勾选就安装不勾不安装"。改为：
- 顶部："下面每一项：勾选 = 装到本机，不勾 = 不装。"
- 两处分区标题也写明"勾选 = 安装，不勾 = 不装"。
- Ollama 已装时："Ollama 已安装（勾选 = 重新安装一次，不勾 = 不装）"。
- 七项 checkbox（Python/JDK/Go/MinGW/Git/Ollama/默认模型）统一以"安装 xxx"开头。

自检：`check_installer_terms.py` 同步更新 —— 修掉上一轮许可页合一留下的旧断言
（还在找已删的 SixCoderTermsCreate/EnableWindow），改为钉 MUI 原生勾选框；新增断言
钉住"无 cmd 黑框、无长 Sleep、文案直白"。`check_installer_terms` / `check_packaging`
全绿，NSIS 编译通过。

### 11.5 内置 Python 漏装 pytest → 所有带测试的仓库都报"用例收集失败"（2026-11-20 晚）

**现象**：安装版里探测任何带测试的仓库，基线一律显示"用例收集失败（导入/语法问题）"。

**根因**：`core/recon.py` 建立基线要跑 `sys.executable -m pytest --collect-only`，
但 `requirements.txt` 按旧注释把 pytest 归到 dev-only，安装包的内置 Python 没装。
`rc != 0/5` → `collect_ok=False` → `collect-failed`；错误尾巴其实是
`No module named pytest`，界面又只显示一句红字，用户看不到真实原因。

**修法**：
- `pytest==9.0.3` 移进 `prototype/requirements.txt`（运行时依赖，不再是 dev-only）；
  `requirements-dev.txt` 只留 mypy。安装包体积 195.4 → 197.0 MB。
- `recon.classify` 遇到 `No module named pytest` 额外写 `collect_reason` 人话。
- 仓库探测面板在 `collect-failed` 时展示 `collect_tail`（pytest 最后几行）+ 排查命令，
  不再只给一个红 badge。
- 自检：`check_packaging` 断言内置解释器 `import pytest` 且 pytest 在运行时清单；

### 11.8 别人电脑真凶：没装 Git，`ensure_demo()` 的 FileNotFoundError 把后端打崩（2026-11-20 深夜）

- 新增 `checks/check_demo_bootstrap.py`：无 Git / Git 抛 OSError / 启动兜底三条；

### 11.15 重启/覆盖安装后 key 被清空（2026-11-21 15:30）

### 11.18 执行时间线不显示夜班过程（2026-11-21 22:45）

用户报障："为什么执行时间线不显示远端的回复了"。

**根因**：夜班默认走**后台长跑**（detached），进度写磁盘、**不发 SSE**；而中栏的
「执行时间线」只由 `/v1/tasks/{id}/stream` 填充（那是「发送」单任务的通道）。
于是夜班跑一整晚，时间线一条都没有 —— 不是网络问题，是这条路径根本没接上。

**修法**：
- 新增 `GET /v1/night/detached/log?repo=&offset=`：按**字节 offset** 增量返回夜班日志，
  自动处理"日志被换成新一夜"（offset 越界回 0）与半行（末尾不完整行留给下次）。
- 前端 `pullNightLog()`：接管到后台夜班后每 2 秒拉一次，逐行 `pushEvent({kind:'night_log'})`
  进主时间线；`summarise` 增加 `night_log` 分支直接显示原文；换日志文件时重置 offset 并插一条提示。
- 非后台模式（SSE）也同步进时间线，两条路径表现一致。
- 顺带统一仓库标签：`paths.night_tag()` 先规范化（`/`、`\\`、大小写、末尾斜杠），
  否则界面传 `F:\WorkSpace\Cut`、命令行传 `F:/WorkSpace/Cut` 会算出两个标签，
  造成日志指针找不到、续跑标记出现两份。

**验证**：`prototype/.tmp/test_night_timeline.py`（Edge + 假接口）——时间线出现 `night_log`、
能看到 `contract_synth`/`author_start` 等真实步骤、offset 推进后不重复；自检
`check_night_detached` [7] 新增 12 条。

### 11.20 甲方模式"直接生成 exe"（2026-11-22 22:45）

用户口径："甲方模式能不能根据需要直接生成 exe"。

**能力**：夜班只保证代码过机械判据，交付物仍是源码目录；现在多一步把它打成
**双击就能跑的可执行文件**。

- `core/exepack.py`：
  · 入口识别 `app/main.py → main.py → src/main.py → cli.py → 带 __main__ 的脚本`；
    并按内容判 **ASGI / GUI / CLI**（ASGI 若直接 onefile 会"起一下就退出"）；
  · 生成启动器到 `.sixcoder/_exe_entry.py`：ASGI 用 `uvicorn.run(app)`，其余 `runpy.run_module`；
  · PyInstaller `--onefile`，成品落 `dist/<名字>.exe`，中间物 `build/_pyi`（不污染仓库）；
  · 解释器优先项目 `.venv`（依赖齐），没有 PyInstaller 时先尝试 pip 安装，失败就如实报错；
  · 状态/日志落 `_logs/pack_<仓库标签>.json|pack_<仓库名>.log`，界面轮询。
- 接口：`POST /v1/night/package`（detached，1-3 分钟）、
  `GET /v1/night/package/status`（状态 + 日志尾 + 是否在跑）。
- 界面：运维行加「打包 exe」+「收工后自动打包」开关；自动触发条件 = 夜班从在跑变为停止
  且需求/规格里出现 `exe|可执行|安装包|桌面程序|客户端|绿色版`；结果可「打开所在目录」。
- 依赖：`pyinstaller==6.20.0` 进 `prototype/requirements.txt`，随安装包一起装进内置 Python
  （安装包 192.7 → 195.3 MB），离线也能打。

**验证**：
- `checks/check_exepack.py` 21 条全绿（四类入口 / 启动器 / 失败人话 / 接口界面 / 依赖随包）；
  设 `SIXCODER_PACK_E2E=1` 可额外跑真打包。
- 安装版实测：内置 `python -m PyInstaller --version` = 6.20.0；临时工程真实打包
  7.6 MB exe 并运行成功（`run: 0 pack demo ok`）。
