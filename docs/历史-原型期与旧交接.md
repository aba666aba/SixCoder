# SixCoder 原型（完整可跑 demo）

本地 AI 编程助手的可运行 demo：**探测仓库 → 计划 → 测试先行 → 补丁 → 闸门 → 审计**，
前端 Vue3 + Vite（非 Streamlit），后端 FastAPI + SQLite，模型 Ollama（本地 **≥7B**）。

> 一键启动在仓库根：`..\start.bat`（或 `..\start.ps1 -Web`）。
> 文档依据：`../docs/`（尤其 12 质量最大化、13 判定权分离、16 诚实验收、17 工程环节补全）。


## 模型要求（硬门槛 ≥7B，实现在 `core/model_policy.py`）

| 用途 | 最低模型 | 建议 |
|---|---|---|
| 单函数 / 单文件（有测试或示例） | **7B** | 7B |
| 多函数模块（含校验/边界） | **7B** | 14B |
| 多模块工程 / 通用助手 | 远端主力 + 本地手脚 | 远端 API 或 32B+ |

**3B / 1.5B 已被代码拒绝**（后端返回 400、CLI 退出码 4、夜班直接报错、界面标"不可选"）：
同一需求、同一套机制实测 **3B 只有机械验收 2/8、独立验收 2/16**，绝大多数失败是
"生成代码无法解析"；7B（纯 CPU 6.9 tok/s）能到 8/8 与 19/19。详见 `../docs/模型门槛与能力边界.md`。
远端是主力：单次约 $0.0005，前缀缓存命中 90%，相比纯远端重写省 95%–99% token 成本。

### 2.000 规划器：模块清单由引擎决定，模型只补细节

**问题**：同一个 4 模块需求，3B 四次跑出 `2 / 2 / 8 / 2` 个节点的计划——它会丢掉"必须覆盖所有模块"。

**改法**（`core/planner.py`，纯确定性代码）：

| 步骤 | 做法 |
|---|---|
| 模块抽取 | 正则从需求里抠 `xxx.py`，并**排除** `test_*.py`/`conftest.py`（实测需求里那句"每个模块都要有 test_models.py / …"会被误当成模块清单） |
| 依赖排序 | 按「被其他模块提及次数」+ 基础/顶层关键词排序：`models → storage → service → cli` |
| 契约切片 | 把需求里**以该模块开头**的那几句原文直接给该模块（`2) storage.py：JSON 持久化`），比 3B 复述准 |
| 骨架 | 每个模块强制一对节点：`test_<m>.py`（先）→ `<m>.py`（后） |
| 合并 | 模型只能**补充契约细节**；它追加的测试/配置路径一律丢弃（实测会追加 `test_models.py` 当实现节点、`test_test_models.py` 当测试节点） |
| 计划闸门 | `validate()`：模块覆盖完整性 + 角色合法性；`sanitize()`：去重、丢掉角色错位节点，并输出清洗说明 |

实测效果（同一中端需求）：

| | 改之前 | 改之后 |
|---|---|---|
| 节点数 | 2 / 2 / 8 / 2（随机） | **稳定 8 个**（4 模块 × 测试+实现） |
| 脏节点 | 无（因为压根没规划） | 首次出现 12 个脏节点 → 清洗后 0 |
| 完成度 | 1/4 模块 | **6/8 节点 done**（4 个模块文件全部产出，2 个实现节点因 3B 代码质量未过闸门） |


### 2.02 needs_human 怎么处理（人工裁决，不伪装成机器通过）

`needs_human` = 引擎判定失败、且升级阶梯用尽的节点。它**只能由人处置**，三种方式都会写入
`evidence_kind='human'` 的闸门记录（不会污染"机器验证"的统计）：

| 处置 | 前端入口 | 后端 | 结果 |
|---|---|---|---|
| **接受（人工放行）** | 右栏节点行「处置」→ 填理由 → 接受 | `POST /v1/tasks/{id}/nodes/{nid}/resolve {action:accept}` | 节点 `accepted`；任务若全部 done/accepted → `done`；审计 `evidence_by_kind` 里出现 `human` |
| **丢弃** | 同上 → 丢弃 | 同上 `{action:drop}` | 节点 `dropped`；任务保持 `needs_human` |
| **继续修** | 工作台「基于此工作区续跑」 | `POST /v1/tasks/{id}/retry` | 以旧工作区为新 repo 新建任务，你可在工作区里先手工改再让它接着跑 |

实测：夹具任务 `t-test-human`（1 done + 1 needs_human）→ 接受失败节点后
`status=accepted`、`task_state=done`、闸门证据 `human_accept ok=1`。

### 2.05 会话快照：退出/崩溃后仍回到原处

`localStorage['sixcoder.session'] = { repo, taskId, ts }`

| 写入时机（三层保险） | 覆盖场景 |
|---|---|
| 仓库输入框 `@input` 防抖 400ms | 手打路径、还没点探测就关页面 |
| 打开任务 / 新建任务后立即写 | 正常操作切换 |
| `beforeunload` + `pagehide` + `visibilitychange(hidden)` | 正常关窗、切后台、刷新 |

| 恢复顺序 | 结果 |
|---|---|
| 1. 快照里的仓库 → 自动探测 | 「优先进入上次结束时的仓库」 |
| 2. 该仓库里**上次正在看的那条任务**仍在 | 直接 `openTask` 回到那个任务（含节点/事件/审计/产物） |
| 3. 那条任务已删除 | 退到该仓库最新任务，并提示 |
| 4. 该仓库没有任何任务 | `resetSession()` 清空会话，开新对话 |

> Electron 被强杀（任务管理器结束进程）时 `beforeunload` 可能不触发，
> 所以前两层（输入防抖 + 切任务即写）才是真正兜底的那层。

### 2.00 计算校验（引擎实测，不靠模型猜）

3B 最顽固的错误是**把测试期望值猜错**：实测 `clamp(5,1,3)` 期望写成 `2`（正确是 `3`）、
`lo>hi` 的异常用例参数写成 `(1,0,5)`（其实是合法区间）。这类错误模型自己不会发现，
测试就永远红，最后只能 `needs_human`。

`core/oracle.py` 用**真实调用**把这件事变成确定性判断：

| 能力 | 做法 | 输出 |
|---|---|---|
| 期望值验算 | 沙箱子进程执行 `module.func(*args)`，与 `expected` 比对 | `oracle` 事件：`期望 2 / 实测 3` |
| 异常用例验算 | 调 `func(*args)` 看是否真抛声明类型 | `oracle` 事件：`期望抛 ValueError / 实测正常返回 1` |
| **自动修 spec** | 搜候选参数（反转/交换/±1/通用兜底 ≤10 组），找到真会抛异常的那组 | `oracle_fix` 事件：`异常用例参数由引擎实测改正为 ['1','5','0']` |
| 前置字面量校验 | `args` / `expected` 必须 `ast.literal_eval` 可解析 | 不合法直接拒绝，不渲染坏测试 |

实测效果：`clamp` 需求从「反复 needs_human」变成 **12 秒 `done`**（闸门 0 失败、变异杀死 2/3、
`calc.py` 里只有一个 `clamp` 定义）。

### 2.0 权限模式（一个下拉框决定能用什么）

| 模式 | capability | 能做什么 | 不能做什么 |
|---|---|---|---|
| **只读勘察** `readonly` | 5 项 | 探测仓库、读文件、检索、看 git 状态/历史/差异、**静态审查** | 写文件、执行命令、提交、推送、跑 Agent（**模型比对也关掉**） |
| **安全编辑** `edit`（默认） | 12 项 | 上面全部 + Agent 改代码 + 跑测试 + 本地提交 + 分支 + 模型语义审查 | **远端同步**（fetch/pull/push/merge/设置远端） |
| **完全授权** `full` | 13 项 | 全部，含远端同步 | 仍然没有：`reset --hard`、`filter-branch`、`gc`、`reflog` |

三层卡口，同一个 capability 定义：


### 2.2 Git：两个通道，权限不同（核心设计）

### 2.1 Git：两个通道，权限不同（核心设计）

| | **人类通道**（UI 按键 / CLI） | **模型通道**（Agent 内部） |
|---|---|---|
| 实现 | `core/gitops.py` + `tools.git_human` | `tools.git` |
| 能力 | **完整 Git 客户端**：init / status / log / diff / branches / stage / commit / fetch / pull / push / sync / merge / switch / new_branch / set_remote / undo / sandbox-undo | 只读 + 快照提交（status/log/diff/ls-files/add/commit/checkout/rev-parse/show/branch） |
| 禁止 | `filter-branch` / `gc` / `reflog` / `replace` / `reset --hard`；`push --force` 需显式且单独记审计 | `push` / `remote` / `config` / `clean` / `reset --hard` |
| 审计 | 每条操作写 `.sixcoder/audit.jsonl`，标记 `human:` | 由闸门与节点快照记录 |

> 为什么分两个通道：**Agent 不该有推送权限**（误操作后果不可逆），但**用户当然需要**
> （提交、拉取、推送、合并本来就是日常工作）。用"操作发起者"区分权限，而不是用一个
> 一刀切的禁列表 —— 这比 SixCoder 那种"谁都能 `git add -A` + `reset --hard`"安全得多。

UI 上的 Git 面板（中栏底部，5 行按钮）：

| 行 | 按钮 |
|---|---|
| 状态行 | 分支 · HEAD · 干净/改动数 · ↑ahead ↓behind · 远端地址 · 当前目标（任务工作区 / 所选仓库） |
| 基础 | **初始化仓库** · 状态 · 历史 · 差异 · 分支列表 |
| 提交 | 提交信息输入 · **暂存全部** · **提交** |

### 2.2 沙箱边界（必须说清楚）

- **能防**：路径越界（`../../Windows/win.ini` ✅拦截）、敏感文件（`.env`/`.ssh`/`keystore`/`*.pem` ✅拦截）、
  网络外联（`curl`/`wget`/`ssh`/`pip install` ✅拦截）、破坏性命令（`rm -rf`/`format`/`shutdown` ✅拦截）、
  提权（`powershell`/`sudo`/`runas` ✅拦截）、凭据泄露（子进程环境里剔除 `*KEY*/*TOKEN*/*SECRET*`）。
- **不能防**：恶意代码执行（Python 解释器本身不受限）、内核级攻击、二进制越权。
- **要更强隔离**：Windows Sandbox / 容器 / 专用低权用户。这一层留作 M4 的 `--sandbox=container`。

### 4.1 3B 卡在哪、怎么解决的

现象：3B **写不出"能覆盖尚未实现功能"的测试**。试过整文件生成 / SEARCH-REPLACE / JSON edits / ops 协议 /
专用测试 prompt 五种方式，全部失败——它写 add/sub 的测试、或把实现写进测试文件。

解法（与 docs/05「确定性后处理」、docs/07「契约先行」一致）：**把测试代码从模型手里拿走**。

```
模型只填「测试规约」槽位（json_mode，300 token）：
  {"func":"divide","module":"calc",
   "normal":{"args":["10","2"],"expected":"5.0"},
   "error":{"enabled":true,"args":["1","0"],"exception":"ValueError"}}
        ↓ 引擎用固定模板渲染（不经过模型）
  import pytest
  from calc import divide

  def test_divide_normal():
      assert divide(10, 2) == 5.0

  def test_divide_error():
      with pytest.raises(ValueError):
          divide(1, 0)
```

配套两个确定性兜底：
- `_autofix_test_imports`：被测函数此刻还不存在，所以 **不能只按"当前导出的符号"补 import**，必须带上
  `extra=[spec.func]`（这是踩出来的坑）
- `red_is_meaningful`：`ImportError: cannot import name 'divide'`（收集阶段失败）**是有效的红**；
  但 `NameError: name 'pytest' is not defined` / `SyntaxError` / fixture 未定义 **不是**
