# 开发者模式：运行与调试（2026-11-20）

## 用户口径

> 开发者模式本身缺乏运行和调试功能，这些要做到位；都有工具链了，自动识别语言选择对应的工具。

确认的两点边界：
- **调试深度**：运行 + 诊断面板（全部语言）**和** Python 真断点单步**都做**。
- **工作目录**：智能判断（向上找项目标志），不固定。

## 做什么

在自带编辑器里打开源码后，头部多出三个按钮：

- **▶ 运行**：按文件后缀自动识别语言 → 用探测到的真实工具链执行 → 底部输出面板显示 stdout/stderr、退出码、耗时；编译型语言（C/C++/Java/Rust）先编译到 `.sixcoder/run/`，编译错误可点击跳到对应行。
- **断点**：在光标所在行下/取消断点（只对 Python 显示）。
- **调试 / ■ 停止调试**：Python 真断点会话。断点停住后显示该行局部变量、调用栈，支持继续 / 单步 / 跳过 / 表达式求值。

其他语言点调试会明确提示"断点调试目前只支持 Python"，**不假装能单步**；但它们照样能运行、看诊断。

## 语言与工具链（自动识别）

| 后缀 | 语言 | 工具 | 运行方式 |
|---|---|---|---|
| .py | Python | 引擎内置 Python | `python -u <file>` |
| .js/.mjs/.cjs | JavaScript | Node | `node <file>` |
| .ts | TypeScript | Node 22+ | 类型剥离直接跑 |
| .java | Java | JDK | javac 编译 → java 运行 |
| .go | Go | Go | `go run <file>` |
| .c / .cpp | C / C++ | MinGW gcc/g++ | 编译 → 运行 |
| .php / .rb / .rs | PHP/Ruby/Rust | 各自工具链 | 解释运行 / 编译运行 |

工具链路径来自 `recon.toolchains()` 的探测链：设置覆盖 > 环境变量 > PATH > 常见目录 > 安装器下载的自带运行时。**装了就能用，没装就明确说缺什么**，不猜。

cw d 智能判断：从文件所在目录向上找 `package.json`/`go.mod`/`pyproject.toml`/`pom.xml`/`Cargo.toml`/`.git` 等标志，命中最近的就用；找不到用文件目录。文件必须在仓库内。

## Python 断点调试实现

- 子进程跑 `core/coderun.py --dbg-worker`，用标准库 `bdb`（pdb 的基类）控制执行；
- 断点命中发 `paused` 事件（含局部变量、调用栈、断点列表），前端轮询事件流实时刷新；
- 控制命令走 stdin 逐行 JSON：`continue`/`step`/`next`/`break`/`unbreak`/`locals`；
- 用户程序输出重定向成事件（分 stdout/stderr），协议用一次性 nonce 前缀 + base64，用户 print 不会污染协议；
- 护栏：空闲 180s 自动收会话，停止/超时杀整棵进程树，不留僵尸。

## 实测踩过的坑（都写进 check_coderun.py 了）

1. `bdb.run()` 收的是**语句字符串**不是函数对象；跟踪函数必须用 `runcall()`。传函数给 run() 会 TypeError，被吞后表现成"断点从不命中"。
2. 断点必须 `set_break(file, line)` 注册进 bdb，只存行号没用——bdb 只在你注册过的行调 `user_line`。
3. worker 子进程不能直接 `python -m core.coderun`：会话里 WorkBuddy 注入 sandbox shim 到 PYTHONPATH，会让 `-m` 找不到 core 包（假故障）。改成直接跑 worker 脚本绝对路径 + 只用标准库。
4. `run.session` 用 `''` 初始化会被 Vue 渲染成 `disabled`（HTML boolean attribute 空串也算有值），必须 `null`。
5. 工具链探测要跑 9 个子进程（3-4s），每开一个文件都探会让运行/调试按钮延迟几秒才可用，像卡住。加 60s 缓存解决。
6. 诊断正则的 file 组要允许 Windows 盘符冒号（`C:\x.py:12:5:`），否则绝对路径错误全解析不出来。
7. "切换断点"按钮原来藏在调试面板里，没启动会话时看不到 → 用户没法先下断点。移到编辑器头部常驻。

## 自检与后端接口

- `checks/check_coderun.py`：语言识别 / cwd 判断 / 真执行 / 诊断解析 / 断点会话 / 超时护栏 / 缓存 / 安全，全绿。
- 后端：`GET /v1/editor/runner`（预检）、`POST /v1/editor/run`（同步运行，超时可调）、`POST /v1/editor/debug/start|cmd|stop`、`GET /v1/editor/debug/events`（轮询）。全部用 `test.run` 权限守卫，路径限制在仓库内。

## 中栏 IDE 与多标签（2026-11-20）

用户口径："左右栏都是可以收缩的嘛，把中栏变成 IDE 就可以有很大页面。"

- 编辑器不再是 `position:fixed; inset:0` 的全屏浮层，而是**直接渲染在 `.col-mid` 里**：左栏文件树常驻（可收起）、右栏可收起，中栏宽度就是最大可用宽度。
- 中栏两态：**工作台**（时间线/需求/审查）与**代码 IDE**；工作台三块用 `v-show` 让位，编辑器用 `v-if="ed.open && midView === 'code'"`。
- 打开的文件是**上方多标签**：点文件树开新标签，点标签切换（`switchTab`），✕ 只关当前标签（`closeTab`）；切标签前 `stashActiveTab()` 保存未保存内容，`saveFile()` 同步回标签快照。
- 模式切换自动换视图：开发者 + 有打开标签 → 代码 IDE；其它模式 → 工作台。只切视图，**标签和未保存内容不丢**。
- 回滚文件走 `openFile(path, true)` 强制重读，避免命中已有标签而不刷新。
- 坑：选中函数识别里写成 `.match(word$)`，浏览器里直接 `ReferenceError: word$ is not defined`，让「定位函数 / 调试此函数」按钮恒失效；源码编译和函数级自检都抓不到。已修为 `.match(word)` 并在 `checks/check_editor_tabs.py` 钉住。
- 浏览器实测（`D:/Python/python.exe prototype/.tmp/test_editor_tabs.py`，Edge + 假接口）：编辑器父节点是 `col-mid`、`position != fixed`、两标签共存、收右栏后编辑器变宽、切模式隐藏/恢复且标签保留、关当前标签另一个还在。

### 19:57 真实项目依赖：优先用项目自己的 .venv（2026-11-20 晚）

用户拿 TCMAI（Django/torch 类真实项目）来探测，收集报 `ModuleNotFoundError`。

**根因**：`recon.classify` 和 `coderun` 原来固定用 `sys.executable`（安装版 = SixCoder
自带 Python，只有引擎依赖）。真实项目的 Django/torch/transformers 装在项目自己的
`.venv` 里，用引擎解释器跑 pytest/脚本必然缺模块。

**修法**：
- `recon.project_python(repo)`：按约定找 `.venv`/`venv`/`env` 的
  `Scripts/python.exe`（Windows）或 `bin/python`（POSIX）；找到就用，找不到退回
  `sys.executable`。
- `recon.classify` 的收集/全量 pytest 都改用这个解释器；`signals` 新增
  `python` / `project_venv`，探测面板显示「项目 .venv」或「引擎 Python」。
- `coderun` 的「运行」和「断点调试」worker 也改用项目 venv 解释器（否则运行也缺依赖）。
- 自检：`check_recon` [9] 钉 venv 检测与 signals；`check_coderun` [2b] 钉运行/调试
  选 venv。TCMAI 实测：建 `.venv` 后 `baseline=verified`、29 条用例收集成功。

**边界（诚实写清）**：只认约定目录，不猜 conda；项目没有 `.venv` 时仍用引擎 Python，
此时缺 Django/torch 会在探测面板显示 pytest 原始报错。正确做法是在项目里建 venv 并
`pip install -r requirements.txt`，SixCoder 会自动用它。

### 21:35 选中即改（解释 / 改 / 补测试 / 找引用）

用户口径："顺手把你说的坐上" —— 把「选中一段代码 → 一个动作」做成开发者模式的入口，
而不是让用户先去聊天框组织一句话。

**交互**：
- 编辑器里选中代码 → 顶部浮出动作条：**💡 解释 / ✎ 改 / 🧪 补测试 / 🔗 找引用**。
- `解释`：四段中文（作用 / 输入输出 / 关键分支与边界 / 风险），不改代码。
- `改`：写一句意图（如"先校验再入库"）→ 模型返回改写 → **行级 diff 预览**（+/- 着色）→
  `接受改动` 才写回编辑器；拒绝/重来不落盘。
- `补测试`：生成 pytest 用例（正常/边界/异常），可 `插入到文件末尾` 或复制。
- `找引用`：用现有 `/v1/editor/symbols` 查当前符号，点击跳转（不花模型 token）。

**安全边界**：
- `/v1/editor/assist` **只返回文本，不写盘**；接受动作在前端，且先校验
  `ed.text === assist.baseText`，防止生成期间文件被改导致错位覆盖。
- 只读模式不允许接受（`canWriteFile()` 检查）。
- 模型源沿用编辑器里的 本地/远端 开关；远端走最强档。

**实现**：
- `server.py` 抽出 `_editor_complete()`（fill/assist 共用），新增
  `POST /v1/editor/assist`（action=explain|edit|test），prompt 分别带
  "不改代码 / 只输出改写后的完整选区 / pytest 正常边界异常" 约束。
- `App.vue` 新增 `assist` 状态、`refreshSelection`、`openAssist/runAssist/acceptAssist`、
  `assistDiff`（LCS 行级 diff，800×800 以上退回整段视图）。
- 自检 `checks/check_editor_assist.py`：路由 / 三种 prompt / 空选区不调用 / 不写盘 /
  界面动作条与 diff；Edge 实测：选中 → 改 → diff → 接受 → 文本写回 → 解释 → 找引用。
