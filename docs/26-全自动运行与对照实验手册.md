## 1. 前置检查（30 秒，跑之前必做）

```powershell
cd E:\AAATOM\NewLai\SixCoder\prototype
python cli.py remote                        # 期望 enabled=true、key_configured=true
python checks/run_all.py                    # 期望"全部通过"（99 个自检；约 10–15 分钟）
```

- `run_all.py` 是**基线证据**：改动之后再跑真实实验，才知道差异是改动带来的还是环境带来的。
- 只跑单条自检：`python checks/check_selfcheck_loop.py`（片内自验）、
  `check_architect.py`（架构问答）、`check_auto.py`（编排层）。
- 远端不可用时不要跑真实实验（会全程空跑并留下"看起来做了很多"的报告）。

## 2. 最短路径：只给一句话

```powershell
python cli.py night --repo D:\myproj --goal "做一个 CSV 记账工具：导入、按月汇总、导出报表" --max-cny 2
```

| 参数 | 含义 | 建议 |
|---|---|---|
| `--repo` | 工作区（会被写代码，别指向重要仓库） | 新建空目录或已有项目 |
| `--goal` | 一句话目标（**不是**需求清单） | 一句能说清"谁能看到什么行为"的话 |
| `--max-cny` | 花费硬顶（人民币） | 小实例 0.5–1；日志域这类 1–3 |
| `--max-slices` | 最多做几片 | 先跑 `2` 试水，再看报告加量 |
| `--max-rounds` | 单切片内循环轮数上限 | 默认 40；限时实验用 15 |
| `--slice-hours` | 单切片时间上限 | 默认 0.5h；限时实验用 0.3 |
| `--fresh` | 忽略已有蓝图重新推导 | 换目标时用；续跑**不要**加 |
| `--approve-plan` | 打印蓝图等人点头才开跑 | 第一次用强烈推荐（2 分钟，不花 token） |

跑完看三样：

```powershell
python cli.py plan show   --repo D:\myproj   # 一页看完：目标/能力/缺口/预算
python cli.py plan cover  --repo D:\myproj   # 真跑探针：到底做完没有（退出码 1 = 没做完）
python cli.py plan trace  --repo D:\myproj --cap cap.cli.count   # 单条能力溯源
```

## 3. 推荐路径：两阶段（先问架构，再全自动）

**阶段 1 · 远端只提问**（一次调用，不写代码）：

```powershell
python cli.py plan ask --repo D:\myproj --goal "做一个日志分析命令行工具：读 access.log，按时间窗统计…"
```

产物：`.sixcoder/questions.json`（10 个左右问题，每个带 `default`）与 `.sixcoder/architecture.md`。

**人给安排**：把答案写成 `.sixcoder/answers.txt`（也接受 JSON）：

```
Q1: 只做单文件一次性统计（其余全部不做）
Q2: 固定粒度分桶（--bucket 1m/5m/1h，按自然边界对齐）
Q3: $ python logstat.py access.log --from 2024-05-01T10:30:00 --to 2024-05-01T11:06:00 --top 2
<<< access.log
127.0.0.1 - - [01/May/2024:10:45:00 +0000] "GET /index.html HTTP/1.1" 200 300
>>>
--- expect
total=3 parsed=3 skipped=0
```

- 缩进＝续行；**`kind=example` 的回答会直接变成权威验收样例**（格式同上：`$` 命令、`<<<` 素材、`--- expect` 期望片段、`--- expect exit: 2` 判退出码）。
- 不回答也能跑：走问题里的 `default`，架构文本会标注`默认`，事后可追责。

**阶段 2 · 拿安排全自动生成**：

```powershell
python cli.py night --repo D:\myproj --goal "…同上…" --answers D:\myproj\.sixcoder\answers.txt --max-cny 2
```

也可以一条命令走完：`--ask`（强制重问）／`--interview`（终端逐条答，回车＝用默认）。

> 人的安排会**逐字进入每一片简报**，`example` 回答升级为权威判据。
> 这一步的意义：把"规格靠猜"换成"读样例"（日志域七跑不收敛的根因就在这里）。

## 4. 对照实验：片内自验到底有没有用（A/B）

### 4.1 设计

| 项 | 设置 |
|---|---|
| 变量 | **唯一**：`--no-selfcheck`（关掉片内自验）vs 默认（开） |
| 固定 | 同一目标、同一架构安排（复用同一份 `questions.json` + `answers.txt`）、同一预算、同一 `--max-slices / --max-rounds / --slice-hours` |
| 两臂 | `D:\Download\exp2a`（对照，关自验）、`D:\Download\exp2b`（实验，开自验） |
| 判据 | `done` 能力数、覆盖率、降级数、代码行、花费（¥）、每百行成本、是否超时 |

### 4.2 必须分离进程（这是踩过两次的坑，不是建议）

**会话内的后台任务会被会话重启杀掉**——`job_run` 起的进程在 dsh 的进程树里，
会话一中断（压缩/切模型/重启），子进程整棵被清掉：钱花了一半、协议文件被截成 0 字节、
结果全丢。实测发生在 19:31 与 20:33 各一次。

所以真实实验一律**脱离会话**，用 Windows 计划任务跑：

**① 写 runner**（`_logs/exp/exp2_run.py`）：两臂顺序跑、每臂结束就落 `exp2_result_<HHMM>.json`、
协议文件**原子替换**（`tmp + os.replace`，被中断也不会变成 0 字节）。

**② 写 wrapper**（`_logs/exp/exp2_wrapper.ps1`）：

```powershell
$ErrorActionPreference = "Continue"
$env:PYTHONIOENCODING = "utf-8"
$env:PYTHONUTF8 = "1"
Set-Location "E:\AAATOM\NewLai\SixCoder"
$stamp = Get-Date -Format "yyyyMMdd-HHmmss"
$log = "E:\AAATOM\NewLai\SixCoder\_logs\exp\exp2_task.log"
Add-Content -Path $log -Value "start $stamp"
& "D:\Python\python.exe" "E:\AAATOM\NewLai\SixCoder\_logs\exp\exp2_run.py" *>> "E:\AAATOM\NewLai\SixCoder\_logs\exp\exp2_console_$stamp.log"
Add-Content -Path $log -Value "done $(Get-Date -Format o) exit=$LASTEXITCODE"
```

> 注意：wrapper 里用**绝对 python 路径**（`(Get-Command python).Source`），
> 计划任务的环境变量与你的终端不一样，靠 PATH 找 `python` 会找不到。

**③ 注册并立刻启动**：

```powershell
$act = New-ScheduledTaskAction -Execute "powershell.exe" -Argument '-NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File "E:\AAATOM\NewLai\SixCoder\_logs\exp\exp2_wrapper.ps1"'
$trg = New-ScheduledTaskTrigger -Once -At ((Get-Date).AddMinutes(2))
$set = New-ScheduledTaskSettingsSet -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries -ExecutionTimeLimit (New-TimeSpan -Hours 2) -StartWhenAvailable
Register-ScheduledTask -TaskName "SixCoderExp2" -Action $act -Trigger $trg -Settings $set -Force
Start-ScheduledTask -TaskName "SixCoderExp2"
```

**④ 确认真的在干活**（别只看"状态: Running"）：

```powershell
Get-ScheduledTask SixCoderExp2 | Select-Object State
Get-CimInstance Win32_Process -Filter "Name='python.exe'" | Select-Object ProcessId, CommandLine
Get-ChildItem D:\Download\exp2a\.sixcoder            # 蓝图/覆盖文件应该开始出现
Get-ChildItem E:\AAATOM\NewLai\SixCoder\_logs\exp\exp2_protocol_*.txt | Select-Object Name, Length
```

**⑤ 收尾（必须做，否则下次还会被旧任务干扰）**：

```powershell
Stop-ScheduledTask -TaskName "SixCoderExp2"; Unregister-ScheduledTask -TaskName "SixCoderExp2" -Confirm:$false
Get-CimInstance Win32_Process -Filter "Name='python.exe'" | Where-Object { $_.CommandLine -match "exp2_run|cli.py night" } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

### 4.3 预算与耗时（实测口径）

- 每臂：`--max-cny 1.5 --max-slices 1 --max-rounds 15 --slice-hours 0.3` → **约 ¥1–1.5 / 臂、15–25 分钟**。
- 一整轮（不限切片）在日志域约 **¥2–3、30–60 分钟**；小实例（CSV 统计，23 条能力）约 **¥0.46、5–10 分钟**。
- 两臂合计预算建议留 **¥4** 上限的余量（含蓝图推导与契约合成的固定开销）。

### 4.4 结果怎么读

| 文件 | 内容 |
|---|---|
| `_logs/exp/exp2_protocol_<HHMM>.txt` | 全过程（两臂命令、stdout 尾部、结果表、`## DONE` 收尾标记） |
| `_logs/exp/exp2_result_<HHMM>.json` | 每臂：`status{caps,done,absent,descoped}`、`code_lines`、`cost_cny`、`took_s`、`timeout` |
| `<工作区>/.sixcoder/blueprint.json` | 能力表与状态、`notes`（含"片内自验：修好 N 条"） |
| `<工作区>/.sixcoder/coverage.jsonl` | 每次观测的 `done/total` 历史（进度曲线） |
| `<工作区>/AUTONOMY.md` | 交付报告：覆盖矩阵、缺口、降级原因、每片账本 |

判定顺序（不要只看覆盖率）：

1. **两臂是否都正常收工**（`timeout=false`）；有一臂超时，结论只能算"半程"；
2. `done` 数与覆盖率——自验臂应显著更高（若无差异，先查自验是否真的被触发：看报告里的 `selfcheck_done` 行）；
3. 每百行成本 = 花费 ÷ 代码行 × 100，和基线 `¥0.129–0.34` 比；
4. 返工分布：`blueprint.json` 里 `why` 字段（同一条能力反复红的原因为同一类，就是接缝问题）。

## 5. 关掉/打开关键机制（做对照时用）

| 开关 | 命令 | 作用 |
|---|---|---|
| 片内自验 | `--no-selfcheck` | 作者不能自己跑验收命令，只能事后判红整片重来 |
| 架构问答 | 不给 `--ask/--answers/--interview` | 完全由模型猜规格（历史失败模式） |
| 人给的验收样例 | `--spec-sample <文件>` | 样例变权威判据（格式见 §3） |
| 计划审核 | `--approve-plan` | 先人审蓝图，再花钱 |
| 续跑 | 不加 `--fresh` | 已通过的能力不重做（蓝图 `done` 保护） |

## 6. 一次合格实验的自查清单

- [ ] 跑之前 `run_all.py` 全绿（否则差异归因不清）
- [ ] 两臂工作区都是**全新**的（旧产物会污染基线）
- [ ] 两臂的 `questions.json` / `answers.txt` 是**同一份**
- [ ] 实验进程**脱离会话**（计划任务），协议文件是原子写
- [ ] 中途只看文件，不打断进程
- [ ] 收尾：停任务、杀残留进程、把结果写进 `_logs/exp/README.md` 与 `_logs/autonomy_runs.md`
- [ ] 结论只写**数出来的**东西，没测到的写"未测"

## 7. 常见坑（每条都真实发生过）

| 现象 | 原因 | 处理 |
|---|---|---|
| 协议文件突然 0 字节 | 进程被中断时 `write_text` 先截断 | 原子写：`tmp` + `os.replace` |
| 后台任务跑着跑着消失 | 会话重启杀掉 dsh 进程树 | 计划任务（§4.2）；别用会话内后台任务跑长实验 |
| 正确实现被判红、错误被判绿 | 同尺寸同秒改写命中旧 `.pyc`（pyc 头是秒级 mtime + 文件大小） | 已修：`run_cmd` 禁写字节码；写入模块时清同名缓存（`check_selfcheck_loop.py` 有回归钉） |
| 计划任务里 `python` 找不到 | 任务环境没有你的 PATH | wrapper 用绝对路径 |
| `--max-slices` 到了还继续跑 | 该闸门按"完成的切片数"算，重规划不计入 | 想限时用 `--slice-hours` + `--max-cny` 兜底 |
| git 收尾报 `bad packed object CRC` | 历史 dangling commit 坏在包里（不在任何分支） | `git config gc.auto 0` 消噪；动 pack 之前先 `git bundle create` 备份 |
