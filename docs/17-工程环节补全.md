# 17 · 工程环节补全：集成 / 追溯 / 安全依赖 / 分级治理

这份文档回应一个问题：**"对比传统软件工程，这套系统还差什么环节？"**
审计结论是差的不是"写代码"那一段，而是**合起来验证、可追溯、可发布、按规模分级治理**这几段。

> **本版更新（2026-11-05）**：原"缺口"清单 8 条里 **5 条已补上**，剩 3 条各有明确理由。
> 每行都写清"落点代码 + 自检 + 有没有接进流程"，不写没有落点的口号。

### 1.1 集成：为什么单元判据不够

一套 8 个函数的流水线，函数级判据可以全绿，业务流仍然可能是错的。
本项目实测到过三种真实形态（都写进了 `check_e2e.py` 的反例）：

1. **清洗器吞字段** → 入库静默丢列（`birth` 永远没被清洗，但每个函数单看都对）；
2. **口径漂移** → `summarize` 的 `count` 与清洗后的条数不是一回事；
3. **分组丢行** → `domains` 计数总和 ≠ 人数。

`e2e.py` 从**契约的类型**里认阶段（`dict→dict` 是清洗、`conn+list[dict]→int` 是入库、
`conn→list[dict]` 是读回、`list[dict]→dict` 是汇总），用**真 sqlite 裸连接**跑一遍，
断言 5 条跨模块不变式：

- ① 清洗产物必须含表里的每一列；
- ② 写入条数 = 清洗后条数；
- ③ 读回的列齐全、id 集合一致；
- ④ 汇总的人数口径与清洗结果一致；
- ⑤ 分组计数总和 = 人数。

认不出完整业务流就**如实跳过**（跳过写进交付报告），绝不猜一条假流程自证清白。

**本轮补强**：字段别名（`date → birth`）现在会进 e2e 的**输入行**，断言仍按规范列查 ——
于是"清洗有没有把别名映射成规范名"变成了真的跨模块不变式。
`night-v2f` 实测 e2e **首次跑通**（`1 passed in 0.06s`）。

### 1.2 追溯：TRACE.md

一张表回答"这条需求凭什么是真的"：需求出处 → 契约函数 → 判据 → 证据强度 → 状态 → 产物行号。
证据强度只认三档：`engine_assertion`（真跑过）> `static_rule`（静态规则）> `none`（无判据）。
**e2e 没跑通时汇总行会明写"整体不算达标"**，不允许拿单函数 8/8 当整体通过。

## 三、仍然空着的三条（附明确理由，不粉饰）

| 缺口 | 现状 | 为什么还没做（不是"忘了"） |
|---|---|---|
| **性能预算** | 无 | 需要场景化基准（吞吐/延迟目标），通用阈值意义不大；应由甲方按业务给数字 |
| **CI/CD 与可复现构建** | 无 | 需要目标仓库自己的构建体系（各语言不同），属"接入层"，引擎层无法替它决定 |
| **对抗性评审（红队，评审者≠作者）** | `review.py` 是单向检查 | 真正要的是"评审者只许举证反例 + 提判据"，需要独立评审预算与会话隔离；在 backlog 里（#21 之后） |

## 四、按代码规模分级的治理

工程环节不是"全都上"，而是**按规模上**（完整分级表见 `docs/24`）：

| 级 | 额外要求 | 现在的状态 |
|---|---|---|
| S | 构建/类型/Lint/单测/密钥 + 一份 AGENTS.md（含 don't-do 配对） | ✅ 全有 |
| M | + 架构依赖方向 / 覆盖率 80% / 工作集声明 / 领域指南 ≤300 行 | ✅ 全有 |
| L | + 变更行变异 ≥70% / 依赖白名单 / 受保护区 / 自定义 Lint 阻断 | ✅ 全有 |
| XL | + 持续健康度与漂移 / 即时反馈 / 治理文件指纹不可变 | ✅ 全有（真实规模未验证，见 backlog #27） |

**每一级都明确了"不做什么"**（`docs/24` §2）：S 级不跑架构测试与变异测试，
M 级不跑变异测试与依赖白名单 —— 因为这些约束的固定成本在那时高于收益。

## 五、复现

```powershell
cd SixAgent\prototype
python checks\run_all.py                 # 全部自检（含反例与不变量扫描）
python tools\trace.py night-v2f          # 生成/刷新 TRACE.md
python tools\metrics.py --last 10        # 聚合指标（花费/验收/命中率/振荡）
python tools\release.py verify           # 发布前体检
python checks\check_invariants.py        # 每条硬编码限制有没有依据
```

## 六、判定权仍然在引擎一侧

新增的所有环节都遵守同一条铁律（见 `plan/13-判定权分离与自认可防护.md`）：
**模型只出代码与建议；通过与否由引擎执行、由证据说话。**

- e2e 的断言由引擎渲染，模型不参与写断言；
- TRACE 的证据来自机械体检；
- 安全规则是静态判定；
- 分级门禁（lint / 类型 / 覆盖率 / 变异 / 架构方向 / 熵）全部确定性；
- **做不到的事情（工具没装、没有 git、没有真仓库）一律如实写"未判定"**，
  不接受"模型说它通过了"。
