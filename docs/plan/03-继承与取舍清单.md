# 03 继承与取舍清单

> 原则：**能继承的是"结构"，不能继承的是"结论"。**
> 任何一方 README 里的说法都必须被代码或实测复核后才写入本项目。

## 一、从 `prototype`（文献助手）继承什么

| 继承项 | 文件 | 为什么它是资产而不是负债 |
|---|---|---|
| ReAct 主循环 | `src/agent/react_loop.py` | 手写而非框架，JSON 协议 + 文本格式兜底 + 解析失败自愈；小模型输出格式经常崩，这层自愈是必需品 |
| 工具注册与容错 | `src/tools/base.py` | `safe_run` **永不抛异常**（失败转成可读 Observation 让模型自我纠正）、JSON Schema 子集校验、`aliases` 参数别名（小模型漏参/传错名极频繁）。这一个文件的价值超过任何提示词技巧 |
| 执行器 | `src/agent/executor.py` | 并行/超时/重试/替代工具/死循环检测，全是编程 agent 的刚需 |
| 混合检索 | `src/retrieval/`（10 文件） | 手写 BM25 + 手写 RRF + 精排 + 四档预设 + Hit@k/MRR 指标。**代码检索和论文检索是同一个工程问题**，直接换语料即可 |
| 索引增量更新 | `src/retrieval/indexer.py` | 正文指纹短路 + `chunk_id` 内容稳定哈希去重，改一行代码不必全量重索引 |
| Ollama 客户端 | `src/generation/llm_client.py` | 已踩过的坑：Windows 上 `localhost` 解析 `::1` 使每次请求多等 2 s、连接复用、分段耗时追踪 |
| 降级矩阵 | 全局 | 无语义模型→哈希；无重排→启发式；无大模型→抽取式。**降级状态显式标注，不静默** |
| 语义缓存 | `src/generation/cache.py` | 3B 上同一步骤重复生成很常见，命中即省一次推理 |
| 轨迹与指标 | `src/observability/` | `TraceRecorder`（环形缓冲 + JSONL）、`MetricsCollector`（Token/延迟/工具成功率/停止原因）、`health_check`（设备/模型/Embedding/向量库/工具齐备性） |
| 配置集中 | `src/config.py` | 业务不硬编码配置；数据目录按 `SR_DATA_DIR` + 特征探测双路定位，仓库可任意搬家 |
| 数据目录探测 | `src/config.py` | 多盘符、多层级、Docker 与本地一致 |
| **490 项离线测试** | `tests/` | **本项目最重要的资产**。不依赖模型与网络，3.5 分钟跑完。改工具集时它就是回归网 |
| 一键验证脚本 | `scripts/verify_*.py`（6 个） | 链路/Agent/引用/GPU/Docker 分段验证 |

**继承时必须接受的两个约束**：

1. **不许改名 `src/` 包**。90 个文件全用 `from src.x import y` 绝对导入，改名成本 > 收益。
2. **不许为了"通过"而删测试**。工具从论文换成代码时，对应测试要**改写**而不是删除；新增工具必须带测试。

## 二、从 `（已删除的旧 Java 服务端）`（Java）继承什么 —— 只继承思路，不继承运行时

| 继承项 | 源文件 | 怎么用 | 注意 |
|---|---|---|---|
| 多 provider LLM 配置（每 agent 独立 provider/key/base-url/model，运行期热更新并回写 yml） | `common/LLMClient.java` + `llm-config.template.yml` | 翻译成 `prototype/src/config.py` 的 `LLMSettings`（主力/升级/辅助三档 + 每档 base_url/model/num_ctx） | **必须修掉掩码回写缺陷**：`maskKey()` 只在展示层用，回写一律忽略掩码值 |
| 任务数据模型（8 张表） | `db/migration/V1~V6*.sql` | 作为 `src/tasks/schema.sql` 的设计参考：任务 / 产物 / 评审 / 用例 / 部署 / 提交 / 流水线日志 / 指令 | 我的任务图多两类：**节点(node)** 与 **闸门记录(gate_run)**，这是 SixAgent 缺的 |
| 真实编译验证 | `service/tester/TesterService.java`（`javac -encoding UTF-8 -d _build`，读退出码） | 推广成通用闸门：`src/gates/build.py` 按 profile 的命令跑，读退出码 | SixAgent 只验 `javac`；我们要验 build+test+compose |
| 项目上下文注入 | `service/ProjectContextService.java`（扫目录、`yml/properties/json/sql` 全文注入） | **反例**：整包塞 Prompt 是 4GB 卡上的自杀行为。我们的做法是检索 + 符号大纲 + 硬上下文预算（见 04） | 别继承"全文注入" |
| Git 集成 | `service/GitService.java` | 保留能力（init/add/commit/diff/HEAD），**改掉破坏性语义**：每步成功 `commit` 做快照，失败 `checkout` 回快照；**禁止 `reset --hard`** | 见下方"事实校正" |
| 人在回路 | `controller/AgentInteractionController.java` + `AgentInteractionPanel.vue` | 翻译成 `approvals` 表 + 前端确认面板：只卡两个点（架构签核、交付签核） | 不是每步打断 |
| 评审→修复→重审循环（`max-rounds: 3`） | `service/reviewer/ReviewerService.java` + `OrchestratorService` | 保留循环思想，但**评审必须是闸门而不是 LLM 评审**（3B 自评不可信） | 见 05 |
| Flyway 式版本化迁移 | `db/migration/` | 用 `schema_version` 表 + 编号 SQL 的轻量等价物 | 不引 Flyway |

## 三、事实校正（README 自述里不成立的说法）

写这份文档时逐条复核过，以下三条**不要照抄**：

| SixAgent README 的说法 | 实测结论 |
|---|---|
| "`git config user.name SixAgent` 缺少 `--`，等价于 `--get`，导致提交身份从未设置、后续 commit 必然失败" | **不成立**。实测 `git config user.name SixAgent`（带值）就是设定操作，之后 `git config user.name` 正常返回 `SixAgent`。真正的 Git 问题是：`GitService` 第 56 行 `git add -A`（把用户所有未提交改动卷进 AI 提交）、第 113 行 `git reset --hard`（破坏性回滚）、`TraceController` 不接 `workingDir` 导致操作落到 `user.dir/output` 而非用户仓库 |
| "部署上线未实现" | 属实。`DeployerService` 只生成一份文档写库，无打包/启动/健康检查 |
| "DAG 编排" | 不属实。代码是有序 `List<String>`，下游依赖靠 `taskId - 1` 猜测，无拓扑排序 |

## 四、明确丢弃（不做、不搬、不修）

| 丢弃项 | 理由 |
|---|---|
| MySQL 8 依赖 + Flyway | 本地单用户工具引入数据库服务是反模式；SQLite 足够 |
| Spring Boot 运行时 | 启动 15–30 s、JVM 内存、打包体积；价值已被 Python 实现覆盖 |
| `shell/release/`（1.2 GB 构建产物） | 打包产物不入库；需要时重新构 |
| Java 的"整包上下文注入"策略 | 4GB 卡上必崩（见 04 上下文预算） |
| LLM 自评审（让模型给自己打分） | 3B 自评几乎恒为"通过"，不如构建/测试闸门 |
| `reset --hard` 式失败恢复 | 破坏性且不携带信息；改为 checkout 快照 + 升级阶梯 |
| 文献助手的 `data/raw`（24 MB 论文 PDF）与 `data/vectorstore` | 版权材料 + 可重建；本项目语料是代码仓库 |
| 文献助手的 `src/frontend/`（Streamlit）作为交付面 | 保留为调试台；交付面是 Electron，避免维护两套 UI |
| 现有 `static/` 目录下 20 个 assets | 与源码不一致的旧构建 |

## 五、继承清单的一句话总结

- **`prototype` 给我们"会干活的发动机"**：工具循环、检索、轨迹、测试网。
- **`shell` 给我们"能安装的外壳"**：Electron + Monaco + NSIS。
- **`（已删除的旧 Java 服务端）` 给我们"数据模型和踩过的坑"**：8 张表、多 provider 配置、真实编译验证、以及三条要避开的错误做法（全文注入、LLM 自评审、`reset --hard`）。
- 真正的新增量是 **`src/codegen/ src/gates/ src/tasks/ src/profiles/ src/delivery/`** —— 把"可交付"变成机器可判定条件的那五件设施。
