## 2. 模型（先拉 coder 版）

```powershell
ollama pull qwen2.5-coder:3b      # 主力：全量进显存，40–55 tok/s
ollama pull qwen2.5-coder:7b      # 升级：约 60–70% 层上卡，9–13 tok/s
ollama pull qwen2.5-coder:1.5b    # 辅助：路由/摘要，100+ tok/s
ollama list
```

| 角色 | 模型 | 用途 | 预期速度 |
|---|---|---|---|
| 主力 `main` | `qwen2.5-coder:3b` | 补丁生成、修编译/测试失败、FIM 小改 | 40–55 tok/s |
| 升级 `strong` | `qwen2.5-coder:7b` | 架构决策、规格化、疑难根因（每单只跑几次） | 9–13 tok/s |
| 辅助 `fast` | `qwen2.5-coder:1.5b` | 路由、摘要、提交信息、命名 | 100+ tok/s |

**不要用 `qwen2.5:7b` 写代码**：同尺寸下 coder 版在 FIM、仓级上下文与语言规范上差距是代差级的。

可选实验（各半天，别先写依赖它的代码）：

- `deepseek-coder-v2:16b-lite-instruct-q4_0` —— 16B MoE，每 token 只激活 2.4B，理论上靠 DDR5 带宽能在 CPU 上跑到接近 3B 的速度、质量接近 7B；但 **prefill 更慢**，只适合"无上下文的长推理"，不适合当主循环。
- `qwen2.5-coder:3b` 的 `q4_K_M` 显式量化 vs 默认量化：显存占用与速度对比。

## 3. Ollama 环境变量（一次性，写系统变量）

```powershell
[Environment]::SetEnvironmentVariable("OLLAMA_FLASH_ATTENTION", "1", "User")   # 4GB 卡省显存的关键
[Environment]::SetEnvironmentVariable("OLLAMA_KV_CACHE_TYPE", "q8_0", "User")  # KV 量化，长 ctx 省一半以上
[Environment]::SetEnvironmentVariable("OLLAMA_NUM_PARALLEL", "1", "User")      # 4GB 卡开并发会互相挤爆
[Environment]::SetEnvironmentVariable("OLLAMA_MAX_LOADED_MODELS", "2", "User") # 3B 常驻 + 7B 按需
[Environment]::SetEnvironmentVariable("OLLAMA_KEEP_ALIVE", "30m", "User")      # 避免每步重载（冷启动 20s+）
```

设置后需重启 `ollama` 服务生效：

```powershell
Get-Process ollama* | Stop-Process -Force
ollama serve    # 或重启 Ollama 桌面程序
```

## 6. 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| 首次提问等 2 秒才响应 | Windows 上 `localhost` 先解析 `::1`，Ollama 只监听 IPv4 | `prototype` 的 `OllamaClient` 已内置 IP 直连修正（`_normalize_base_url`），若自写客户端注意别用 `localhost` |
| 长上下文一步要 1–2 分钟 | prefill 掉到 CPU（模型 offload 或 ctx 太大） | 降 `num_ctx`；确认 3B 全量在卡上（`ollama ps` 看 PROCESSOR 列）；路径走上下文预算 |
| `ollama ps` 显示 100% CPU | 显存不足或 `OLLAMA_NUM_PARALLEL>1` | 设 `NUM_PARALLEL=1`、`FLASH_ATTENTION=1`、`KV_CACHE_TYPE=q8_0` |
| 每步之间都重新加载模型 | `KEEP_ALIVE` 太短 | 设 `30m` |
| 测试从 490 掉到 489 | 删了被断言的目录（如 `data/vectorstore`） | 恢复目录 + `.gitkeep`；删目录前先改测试 |
| 换模型后检索结果异常 | Embedding 维度变化，索引与新向量维度不匹配 | 全量重建：`python scripts/build_index.py --rebuild` |
| Electron 起不来后端 | `main.cjs` 仍 spawn `java -jar` | M3 改为 spawn `python -m src.api`；过渡期手动先起 8760 |

## 7. 版本与依赖纪律

1. **`requirements.txt` 不锁上限的历史问题**：新增依赖时**钉住版本**（`==`），至少在 CI 里冻结一次 `pip freeze`。
2. **重依赖惰性导入**：`sentence-transformers` / `chromadb` / `rapidocr` 必须保持惰性导入，缺件走降级矩阵，不许在模块顶层 import 后崩。
3. **可复现**：`ollama pull` 的模型 tag 写进 `profile.yaml` 的 `model` 段，不使用 `:latest`。
4. **不在仓库里放模型权重与语料**：`models/`、`data/raw/`、`workspaces/` 全部进 `.gitignore`。
