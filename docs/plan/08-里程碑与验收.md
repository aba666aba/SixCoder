### 风险清单（按危害排序）

| 风险 | 影响 | 缓解 |
|---|---|---|
| 4GB 显存下 prefill 走 CPU，长上下文不可用 | 单步从 20 s 变 2 分钟，任务无法完成 | 上下文硬预算 3,500 token（04 §4）；7B 只在 ≤2K 上下文时升级 |
| 3B 写出的测试恒真（反幻觉失效） | 闸门形同虚设 | 强制"测试先红后绿"；**变异测试量化**（12 §4-M3）；AST 检查断言存在（05 §5） |
| 3B 用"改测试/放宽断言/吞异常/降编译目标"绕过闸门 | 质量系统性作假，且经验库会放大 | `anti_cheat.py` 七类检测（12 §4-M7），每节点跑 |
| 变异测试首跑极慢（PIT 编译变异体） | 批次墙钟超标 | 只在批次/交付前跑（12 §5 跑频设计）；只对**改动文件**变异 |
| 用户机器多版本 JDK/Node 冲突 | "能编译不能运行"类诡异错误 | 所有命令经 `toolchain/exec.py` **显式注入** JAVA_HOME/PATH（11 §2.4） |
| 自动选型选了一个本机跑不了的栈 | 交付必然失败 | 环境可用性作为**硬约束**参与打分（11 §1.2） |
| Profile 抽象漏了，加第二个栈要改引擎 | 通用性承诺破产 | M3 只做一个 profile，加第二个时若需改引擎则先修抽象（07 §6） |
| Spring Boot 构建慢（`mvn` 每次 20–40 s） | 节点墙钟超 3 分钟预算 | `-o` 离线 + 增量 + 闸门降级（先 G1+G5，全量 G2 放集成阶段） |
| 生成大量文件后无人能审 | 交付不可控 | `.sixcoder/report.md` 的"需求→测试映射 + NEEDS_HUMAN + 质量分"；人工只签核两处 |
| `needs_human` 比例过高（> 30%） | 失去自动化价值 | 优先补 profile 模板与能力清单，而不是换更大模型 |
