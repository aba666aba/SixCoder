# 01 总体设计

## 1. 目标与非目标

### 1.1 目标（可验收的产品承诺）

输入：一段自然语言需求（加技术栈 profile 指定）。
输出：一个**可交付的代码仓库**，满足 8 条交付门禁（见 07）：

- 空目录起 `git clone` → 一条命令构建 → 测试全绿
- CI 配置在内且可本地等价执行
- `docker compose up` 能起，健康检查 200
- 数据库迁移可向前执行、可重放
- `.env.example` 齐备、无明文密钥
- README 里每条命令都**真跑过**
- 日志 / 错误处理 / 健康检查三件在位
- 需求 → 验收测试映射表存在，每条需求至少 1 个测试引用

### 1.2 非目标（明确不做，写进产品文案）

| 不做 | 原因 |
|---|---|
| 全自动无人值守交付 | 3B 模型无法承担全局架构判断，强行承诺必然翻车 |
| 支持任意技术栈 | 通用性靠 profile 数量横向扩张，不靠模型万能 |
| 处理超大既有仓库的大规模重构 | 4GB 显存 + 2–4K 上下文预算，跨文件大改不可行 |
| 替代工程师 | 定位是"把工程师从 3 天压到 3 小时" |

### 1.3 质量承诺的唯一口径

**通过率 = 通过全部自动闸门的任务数 / 启动的任务数**，按 profile 分档统计，写进 README。
不承诺"看代码好不好"，只承诺"机器能验的都验了"。

## 2. 进程边界（三进程，两条连接）

```
┌──────────────────────────────┐
│ Electron 外壳                 │  shell/
│  - 窗口/菜单/NSIS 打包         │  electron/main.cjs
│  - Vue3 + Monaco + diff 视图   │  src/views/*
│  - 启动时拉起 Python 服务      │
└───────────┬──────────────────┘
            │  HTTP + SSE（127.0.0.1:8760）
┌───────────▼──────────────────┐
│ prototype（Python 3.12）     │  prototype/
│  - FastAPI 服务层             │  src/api/
│  - ReAct Agent + 工具          │  src/agent/, src/tools/
│  - 代码检索（复用混合检索）      │  src/retrieval/
│  - 闸门执行器（构建/测试）       │  src/gates/
│  - 任务图与状态机              │  src/tasks/
│  - Profile 与模板             │  src/profiles/
│  - SQLite（任务/产物/轨迹）      │  data/sixcoder.db
└───────────┬──────────────────┘
            │  HTTP（127.0.0.1:11434）
┌───────────▼──────────────────┐
│ Ollama                        │
│  qwen2.5-coder:3b（主力）      │
│  qwen2.5-coder:7b（升级）       │
└──────────────────────────────┘
```

**为什么不是四进程（不把 Java 放进主链路）**

| 维度 | Java 进主链路 | Python 单核（选定） |
|---|---|---|
| 运行时依赖 | JDK17 + Maven + MySQL8 | Python 3.12（已装）+ SQLite |
| 启动耗时 | 15–30 s（JVM + 数据源 + Flyway） | < 1 s |
| Agent 能力 | 需从零实现工具循环、检索、重试 | 已有 ReAct + ToolRegistry + 检索 + 490 测试 |
| 已知缺陷 | `git config` 少 `--`、key 掩码回写、API 无鉴权等约 30 条 | — |
| 打包体积 | backend.jar + JRE 或要求用户装 JDK | 单一 Python 进程 |

结论：Java 层的价值是**数据模型与流程经验**，不是"运行时"。把它翻译而非搬运。

## 3. 技术选型决策记录（ADR 摘要）

### ADR-1：保留 `prototype/src/` 包名，不改名不改结构
搬进来的 90 个 .py 全部用 `from src.x import y` 绝对导入。改名要动 90 个文件并有可能打破 490 项测试。
**决定**：`prototype/` 内部结构完全不动，新模块以 `src/codegen/ src/tasks/ src/gates/ src/profiles/ src/api/` 平行加入。

### ADR-2：新增 FastAPI 服务层，而不是让 Electron 直接跑 CLI
理由：需要 SSE 流式推送轨迹（前端轨迹树是已有能力，`src/observability/tracer.py`）、需要并发控制（4GB 卡必须串行推理）、需要打包后单一入口。
**同时保留 CLI**（`python -m src.cli`），便于无界面回归测试。

### ADR-3：SQLite 而非 MySQL
任务图、产物、闸门记录都是单机单用户的量级；SQLite 零部署、可随仓库迁移、便于把一次完整运行导出成可复现的归档。
表结构参考 `（已删除的旧 Java 服务端）/src/main/resources/db/migration/*.sql` 的 8 张表（TaskInfo/CodeArtifact/ReviewRecord/TestCase/DeployRecord/GitCommitLog/PipelineLog/AgentCommand）设计，但**不用 Flyway**，用 `src/tasks/schema.sql` + 版本号字段做轻量迁移。

### ADR-4：目标仓库用独立目录 + git 分步快照，绝不在用户工作区直接跑
每个任务在 `workspaces/<task_id>/` 建独立仓库副本；每步成功 `commit`（快照），失败 `checkout` 回快照——**不是 `reset --hard`**。
这条是对 SixAgent 破坏性行为（每步 `git add -A && commit`、失败 `reset --hard <hash>`、`TraceController` 操作错目录）的直接修正。

### ADR-5：模型分级 + 单并发
4GB 显存只能容纳一个模型实例。所有推理请求走**单一队列**（`src/api/queue.py`），保证：
- 3B 常驻不反复加载（冷启动 20 s 会摧毁节奏）
- 升级到 7B 时从容换出，且升级请求插队到队首
详见 09 的 Ollama 参数。

### ADR-6：不做代码解释器式"任意执行"
`bash` 工具只允许：白名单命令（构建/测试/lint/git/包管理）+ 固定工作目录 + 超时 + 输出截断。
任何越界请求直接返回可读拒绝（"工具 bash 调用失败：命令 git push 不在白名单"），让模型自己换路子，而不是抛异常中断循环。

## 4. 端到端数据流

```
[0] 仓库探测（确定性，只读，见 10）
    git/文件系统信号 → 形态判定：GREENFIELD / SCAFFOLDED / BROKEN_BASELINE / YOUNG / GROWING / MATURE
        │  形态决定后续一切策略（上下文来源、补丁预算、必过闸门）
        │  若 BROKEN_BASELINE → 先"建立可验证基线"，功能需求后置
        │
[1] 需求录入 + 技术栈自动选型（见 11）
    用户：文字需求（可不指定栈）
    系统：能力求交 + 环境可用性 + 仓库惯例 → 打分 → 推荐 top1 并解释"为什么不是 top2"
        │
[2] 能力求交（确定性，非模型）
    需求动词 → profile.capabilities；不命中 → 立刻返回"不支持清单"，不进入开发
        │
[3] 规格化（3B，结构化输出）
    需求 → 实体/字段/角色/约束（JSON Schema 约束）→ 用户确认一次
        │
[4] 契约生成（3B + 模板）
    OpenAPI 片段 / DDL / 接口签名 / 测试骨架（红）
    闸门：schema 校验 + DDL 可执行 + 骨架可编译
        │
[5] 任务图展开（确定性）
    契约 → 节点 DAG：每个节点 = 1 个文件 / ≤120 行 / 1 个测试契约
        │
[6] 逐节点执行（Agent 循环 + 闸门 + best-of-N）
    for node in ready_nodes():
        patch = generate(SEARCH/REPLACE, ctx ≤ 2–4K)
        ok    = gates(patch)            # 语法→构建→类型→lint→测试
        if not ok: escalate(node)       # 7 级阶梯，见 06
        commit(snapshot)
        │
[7] 集成组装（确定性 + 模板）
    main 装配 / 配置 / migrations / Dockerfile / compose / CI / README
    闸门：docker compose up + 健康检查 + 全量测试
        │
[8] 交付门禁（8 条）+ 人工签核
    产出：仓库路径 + 交付报告（需求→测试映射、NEEDS_HUMAN 清单、指标）
```

**关键点**：步骤 [2][5][7] 是确定性的（代码 + 模板），只有 [3][4][6] 依赖模型。
把非模型的环节做扎实，模型才只需要承担它真正擅长的那一小段。
