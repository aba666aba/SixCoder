# SixCoder

**让 AI 替你写代码 —— 但不许它骗你。**

![python](https://img.shields.io/badge/python-3.12-3776AB)
![checks](https://img.shields.io/badge/自检-99%20项-brightgreen)
![acceptance](https://img.shields.io/badge/真实项目-44%2F44%20机械验收-success)
![license](https://img.shields.io/badge/license-见%20LICENSE-blue)

> 你提需求，它拆任务、写代码、跑机械判据、出交付报告。
> 报告里写清**过了什么、没做什么、花了多少钱**——错了会红，做不了会说"测不了"，绝不假装通过。

---

## 为什么要有它

用 AI 写代码，最痛的不是"写不出来"，而是这三件事：

| 你的痛 | 别的工具 | SixCoder |
|---|---|---|
| 😰 它说"已完成"，你敢信吗？ | 让你自己 review | **44 条机械判据 + 真实数据库往返**，不过就红 |
| 😰 一个个函数都对，合起来跑不通？ | 不管 | **跨模块集成冒烟**：所有模块一起 import、按签名调用 |
| 😰 函数都对，业务还是错的？ | 不管 | **业务流不变量**：唯一性、容量上限、优先级、汇总口径一致 |
| 😰 页面返回 200 就代表能用？ | 不管 | **真起服务真发请求**：未知路径要 404、坏 JSON 不许崩 |
| 😰 一晚上花掉多少钱？ | 事后看账单 | **￥ 硬上限**，到顶即停，报告写明"花费到上限" |

一句话：**它不承诺"代码一定对"，但承诺"它没说谎"。**

---

## 它到底交付什么

一次夜班跑完，你拿到的是：

```
✓ 能跑的代码            15 个模块 / 44 个函数 / 1813 行，真编译真运行
✓ DELIVERY.md 交付报告   验收几条、哪条没过、为什么、哪些门禁没做
✓ TRACE.md 追溯矩阵      需求条目 ↔ 契约 ↔ 判据 ↔ 证据（甲方"三十秒答出来"）
✓ 自动化测试             pytest 通过，覆盖率实测（不达标会写明）
✓ 成本账单               花了 ¥0.5 还是 ¥0，几次远端调用，有没有触顶
✓ 能力上限台账           八项上限的当前值 + 差在哪 + 下一步
```

而且**这些数字都能自己复核**：`python checks\run_all.py`（99 项自检，全绿才算数）。

## 安装与首次运行（照着抄就行）

下面每一条命令都在 Windows 10/11 + Python 3.12 上实测跑过；Linux 把 `py` 换成 `python3` 即可。

### 0. 前置

| 必需 | 说明 |
|---|---|
| **Python 3.12** | `python --version` 应输出 `3.12.x` |
| **Ollama + 一个 ≥7B 的代码模型** | 本地工人模型，缺了就跑不了夜班（系统会如实报"没有可用本地工人模型"，不会假装能用） |
| Git | 隔离层要按文件回滚，需要 `git` |
| 可选：JDK / gcc / node | 只有写 Java / C / C++ / JS / TS 时才需要；缺了会在开跑前**如实拒绝、零花费** |

### 1. 拉代码、装依赖

```powershell
git clone https://github.com/aba666aba/SixCoder.git
cd SixCoder
python -m venv .venv
.\.venv\Scripts\Activate.ps1          # Linux/macOS：source .venv/bin/activate
python -m pip install -r prototype\requirements.txt
```

> 想跑自检再装一份开发依赖：`pip install -r prototype\requirements-dev.txt`（pytest / mypy）。

### 2. 装本地工人模型（一次性）

```powershell
ollama pull qwen2.5-coder:7b
```

### 3. 验证安装是否正确（这一步会告诉你还差什么）

```powershell
cd prototype
python cli.py doctor
```

正常输出长这样（工具链那几行按你机器实际有就显示，没有会写"不可用"）：

```
Ollama        [在线]  models=qwen2.5-coder:7b, qwen2.5:7b
默认模型      qwen2.5-coder:7b
Python        3.12.10
数据库        ...\prototype\data\proto.db
工具链        3/7 可用
  [OK] python  3.12.10  ...
```

`Ollama [在线]` + `默认模型` 有值 = 可以开跑了。

### 4. 起服务 / 或直接命令行

```powershell
# A. 图形界面（浏览器打开 http://127.0.0.1:8760）
python server.py

# B. 命令行跑一次夜班（先小预算试水，¥0.2 封顶）
python cli.py night --repo D:\code\myproj `
  --requirement-file D:\code\myproj\需求.txt `
  --scale S --hours 0.1 --max-cny 0.2

# C. 看交付报告
notepad D:\code\myproj\DELIVERY.md
```

### 5. 装机自检（可选，20 项环境无关 + 全部判据）

```powershell
python checks\run_all.py
```

说明：少数自检项依赖本机工具链（如 C++ 真编译要 g++）。缺的时候会打印
`SKIP ... 测不了`，**不计为通过**，也不会因此判失败——这是有意的诚实口径。

### 装不上/跑不起来时

| 现象 | 原因 | 修法 |
|---|---|---|
| `[FAIL] Ollama 不可达` | Ollama 没启动 | `ollama serve`（或启动桌面端）后重试 |
| `默认模型` 是空的 | 一个模型都没拉 | `ollama pull qwen2.5-coder:7b` |
| 夜班报"缺工具链：go/java…" | 本机没有对应编译器 | 装好再加进 PATH；**这一步不花钱** |
| `ModuleNotFoundError: fastapi` | 依赖没装/装到别的解释器 | 确认已激活 venv，再 `pip install -r prototype\requirements.txt` |
| 端口被占用 | 8760 已被别的程序用 | `python server.py --port 8761` |
| 自检里出现 `SKIP` | 本机缺该检查要的能力 | 属正常；要看某项为何跳过，单独跑那条脚本 |

## 只给一句话：全自主模式

不想写需求清单？给一句话就行，**切片和验收对象由系统自己规划**：

```bash
sixcoder night --repo D:\myproj --goal "做一个 CSV 记账工具：能导入、按月汇总、导出报表" --max-cny 2
```

它自己做的事（顺序固定，每一步都有机械判据）：

1. **能力表**：把目标翻译成一串**可观测行为**（"跑这条命令打印出 3"才算一条能力，不是"写完 models.py"）
2. **独立评审**：换一个上下文再审查一遍这张表，专挑四类问题：漏了什么、重复了什么、依赖顺序断了、探针空壳也能过
3. **切片**：按依赖拓扑序装成"一轮能干完"的小片（剂量按当前思考强度算），每片闭合 —— 做完立刻能被观测
4. **逐片生成**：每片现生成一份可机判的契约，然后用夜班流水线做（体检→派工→写码→机械验收）
5. **重新观测**：每片做完就**真跑一遍全部探针**，看整个项目到底做完没有（顺带获得项目级回归网）
6. **停滞就重规划**：连续几片没有新进展，或某条能力反复失败 → 补能力 / 重连依赖 / 降级（降级必须写原因）
7. **收工出报告**：`AUTONOMY.md` —— 覆盖矩阵、缺口、降级原因、每片账本、续跑命令

### Web 目标（FastAPI / HTTP 服务）

目标是 Web 服务时，验收不走 CLI，而是**真发 HTTP 请求**：`http` 探针支持多步链
（注册 → 登录 → 带 token 访问）、跨进程回读（判数据真落盘）、并发 N 次 + 条数（判丢写）、
幂等（重复提交必须 4xx）。路由、请求体模型、依赖安装、`.env` 都由引擎确定性生成，
作者只写服务层函数——否则"路由没挂"会被记成"能力做不出来"。

交付前另有一道体检：应用可导入 / `/docs` 200 / **uvicorn 真启动** / README / requirements /
引擎生成的 pytest。

> 诚实边界：这一层是 2026-11-07 才补齐的。实测 17 条能力（9 业务 + 8 机制）中 **6 条通过**，
> 剩余归因都在远端能力侧；产物约 220 行，离 XL（≥10000 行 + 前端）还很远。
> 机制细节与标定数据见 [docs/27](./docs/27-Web项目的验收与交付机制.md)。

看进度与溯源（都不花一次远端调用）：

```bash
sixcoder plan show   --repo D:\myproj                # 一页看完：目标/能力/缺口/预算
sixcoder plan slices --repo D:\myproj                # 下一刀切在哪
sixcoder plan cover  --repo D:\myproj                # 真跑探针：到底做完没有
sixcoder plan trace  --repo D:\myproj --cap cap.cli.count   # 这条能力的来龙去脉
```

预算怎么估：实测 **¥0.12 / 100 行**（一次通过时）。全自主模式和需求模式用同一套计量，
`--max-cny` 是总闸，单片最多吃掉总额的 15% —— **一处困难不会拖死整个项目**。

第一次用建议加 `--approve-plan`：它会把那张能力表打印成一页，你点头才开跑（2 分钟）。
这就是"人只审方案、不审 1 万行代码"的那个位置。

### 前期打框架：先让远端就架构提问，人给安排，再全自动生成

只给一句话时，最贵的错误不是写不出代码，而是**规格靠猜**：入口叫什么、空值怎么算、
错误怎么写、什么算"做完"。所以默认推荐两阶段（人只在最贵的位置介入一次）：

```bash
# 阶段 1：远端只提问（一条命令，10 个左右问题，每个都带建议默认）
sixcoder plan ask --repo D:\myproj --goal "做一个 CSV 记账工具：导入、按月汇总、导出报表"

# 人把答案填进 .sixcoder/answers.json（也认 `Q1: 答案` 逐行写法）
# 阶段 2：拿着安排全自动生成，人不再介入
sixcoder night --repo D:\myproj --goal "…" --answers .sixcoder/answers.json --max-cny 2
```

也可以一条命令走完：`--ask`（强制重问）／`--interview`（在终端逐条答，回车＝用建议）。

三份落盘、都可追溯：

| 文件 | 内容 |
|---|---|
| `.sixcoder/questions.json` | 远端提的问题（为什么问、选项、**建议默认**） |
| `.sixcoder/answers.json` | 人的回答（没答的留空 ＝ 用默认） |
| `.sixcoder/architecture.md` | 渲染后的架构安排，每条标注`人答`/`默认` |

这套安排会**逐字进入每一片简报**（不只是蓝图提示词）——写代码那一步看得到才算数。
其中 `kind=example` 的回答直接变成**权威验收样例**（同 `--spec-sample` 格式）：
人给一条"怎么跑 + 输入什么 + 该看到什么"，就不再需要模型去猜输出格式。
人不回答也能跑（走默认），但架构文本会注明哪条是默认，事后能追责。

### 片内自验：让作者自己跑一遍验收命令

以前作者是**盲写**的：探针在切片之外跑，判红之后整片重来 —— 一轮就是一次全赔。
现在每片跑完，引擎会把"没过的能力 → 验收命令 → **真实 stdout / stderr / 退出码**"
交给作者，并用**多轮对话**让它自己修（它能 @RUN 跑命令看输出、交回整份文件）：

```
每步：引擎先跑探针拿真实证据 → 作者 @RUN 自验 → 交回整份文件 → 引擎再跑探针 → 判
上限：默认 3 步（SELFCHECK_STEPS），预算用尽/步数到顶/空转都会立刻停
```

硬边界（不是普通 shell，是"跑验收命令"的通道）：

| 边界 | 规则 |
|---|---|
| 命令 | 只许 `python` / `py` / `pytest`；管道、重定向、串联、删除、联网、装包一律拒 |
| 工作目录 | 锁在仓库内；输出尾部截断 |
| 写入 | 只许改本片声明的模块；越界/空文件/省略号整份退回 |
| 判定权 | **永远在探针**：作者说 `@DONE` 不算数，改完必须重新观测 |

关掉它做对照实验用 `--no-selfcheck`；平时别关。

顺手修掉一个真 bug：作者自己跑 `python x.py` 会生成 `.pyc`，而 pyc 头里是**秒级** mtime +
源文件字节数 —— 同一秒内改写同尺寸内容时，CPython 认为缓存有效，继续跑**旧字节码**，
正确的实现被判红、错误的被判绿。现在跑命令一律禁写字节码，写入模块时顺手清掉同名缓存。

## 适合谁用

### ✅ 非常适合

- **教学项目 / 课程作业 / 内部工具**：需求能写成"函数 + 返回什么 + 示例"，它就能交活。
- **要第一版能跑的版本**：不要求漂亮，要求"接口对、接得上、跑得起来"。
- **教学与复现**：每一步都有判据、有证据、有成本记录，适合当教材案例。
- **给代码做机械体检**：契约、边界、数据库往返、模块接线，一条条过。
- **多语言小模块**：Java/C/C++/JS/TS 真编译真运行（没工具链的语言会开跑前拒绝，不花钱）。

> 系统形态不限：只要需求能写成**函数契约**（签名 / 返回形状 / 示例），它就按同一套机械判据验收。
> 工具库、CLI、数据持久化层、纯算法模块、轻量 Web 服务，走的是同一条流水线。

### ❌ 请别用在

- **大型 / 遗留 / 多团队工程**（>1 万行尚未验证）—— 别拿它重构你的祖传代码。
- **前端交互、视觉、移动端、桌面 UI** —— 它验接口和数据，不验"好不好看、顺不顺手"。
- **依赖第三方服务 / 私有 SDK / 需要联网**的项目 —— 默认只用标准库，不自动装依赖。
- **安全关键、金融、医疗、涉密** —— 产物必须人工逐行签字，本工具不承担这个责任。
- **业务规则复杂、语义至上**的系统 —— 业务流判据按"唯一性 / 容量 / 优先级 / 汇总口径"
  四类通用不变量生成，覆盖不到你特有的业务语义；测不了会如实写"不适用"，不会假装通过。

## 能力上限：我们主动交底

> 不喜欢"业界领先"这种词，只给能复核的数字。全部可用 `DELIVERY.md` 的台账或自检复核。

| 维度 | 当前实测 | 说明 |
|---|---|---|
| 已验证规模 | **15 模块 / 44 函数 / 1813 行** | 一个真实项目完整跑通 |
| 单函数机械验收 | **44 / 44** | 契约示例 + 边界 + 真实 sqlite 往返 |
| 业务不变量 | **16 / 16**（两套场景） | 容量充足 / 容量不足 |
| 真实 HTTP 端到端 | **8 / 8** | 真起服务真发请求 |
| 跨模块接线 | 15 模块、44 函数，0 失败 | 一起 import + 按签名调用 |
| 测试覆盖率 | **50%**（M 档地板 80% → 不达标） | `coverage` 真测量，不猜 |
| 并发 | **串行** | 并行有 429 与"读到中间态"风险，默认关 |
| 数据流 | 只有**参数来源链** | 没有污点追踪（不硬吹） |
| 语言 | Python 端到端；Java/C/C++/JS/TS 真跑 | Go/C#/Rust/PHP/Ruby 明确拒绝 |
| 规模档位 | S ≤10 万 / M ≤50 万 / L ≤100 万 / XL >100 万 | **只有 S 档有实证** |
| 本地模型 | **≥4B**（默认 `qwen2.5-coder:7b`） | 1.5B/3B 直接拒 |
| 花费 / 耗时 | 15 模块约 **¥0.5 / 300 秒** | 达标后复跑常为 ¥0 |

**八项上限、各自的"差在哪 + 下一步"，每次跑完都会打进交付报告。**

## 三种模式：谁在拍板，你自己定

| 模式 | 权限与协作方式 | 适合谁 |
|---|---|---|
| **只读** | 只读代码、出分析、给建议，**不写任何文件** | 只想让它看代码 |
| **开发者** | 能写文件；但"出方案"和"关键提交"要你点头 | 你定架构，它干活 |
| **甲方** | 你只提需求，架构与实现它内部决定，只汇报结果 | 想尽快拿到能跑的成品 |

## 凭什么信它：四层证据

1. **单函数判据** —— 契约示例、边界矩阵（空/None/缺字段/超长/类型错）、该抛异常必须抛、真实数据库写→读往返。
2. **跨模块接线** —— 所有模块一起 import、公开函数按签名真调用，抓"函数都对、合起来炸"。
3. **业务流 e2e** —— 跑通一条端到端业务链，断言四类通用不变量（唯一性 / 容量上限 / 优先级 / 汇总口径）。
4. **能力上限台账** —— 八项上限现算现报，测不了就写"测不了"，绝不冒充通过。

**铁律**：每修一个真实 bug，就留一条断言。所以自检只会越来越多（现在 99 项），不会越来越少。

## FAQ

**Q：不装 Ollama，只用远端大模型行不行？**
A：不行。本地工人模型是设计的一部分（先本地写、写不出来才升级远端），没有它跑不起来。

**Q：它说"44/44 通过"，是不是就代表系统没问题？**
A：不是。44/44 只代表"44 个函数符合契约、模块接得上、业务不变量成立、HTTP 活得下来"。
报告里同时列了没做的门禁（覆盖率不足、没做并行、没有污点追踪）——那才是真正的风险区。

**Q：能接我自己的模型吗？**
A：能。界面「设置 → 远端模型」里填 base_url / model / api_key，支持多档位。

**Q：跑坏了怎么办？**
A：每次尝试都在隔离层里跑（git 分支或整工作区快照），失败整层丢弃、成功才并回；
界面另有「撤销该文件」「沙箱撤销」两个手动兜底。

**Q：为什么报告里会写"测不了"？**
A：因为那件事真的测不了（比如当前项目没有 Web 层、本机没装覆盖率工具）。
我们宁可写"测不了"，也不把它算成"通过"。
