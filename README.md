# SixCoder

**一个会自己写码、但必须先证明自己没撒谎的代码生成引擎。**

![python](https://img.shields.io/badge/Python-3.12-3776AB)
![backend](https://img.shields.io/badge/FastAPI-SQLite-009688)
![frontend](https://img.shields.io/badge/Vue3-Vite-42B883)
![desktop](https://img.shields.io/badge/Electron-可选-47848F)
![checks](https://img.shields.io/badge/自检-145%20项-brightgreen)
![license](https://img.shields.io/badge/license-AGPLv3%20%2F%20商业双许可-blue)

> 给一份需求，它拆能力蓝图、合成契约、调模型写码、跑机械判据与真实 HTTP 探针，
> 最后交一份写明「过了什么 / 没做什么 / 花了多少钱」的报告。
> 不承诺代码一定对，只承诺**报告没说谎**：错了会红，测不了会写"测不了"。

这是一个把**软件工程纪律**做成机械约束的作品：判据优先于生成，证据优先于说辞。

---

## 技术栈

| 层 | 选型 | 在作品里的作用 |
|---|---|---|
| 编排与引擎 | Python 3.12、`core/` 模块化 | 夜班主循环、蓝图、切片、断点续跑、预算闸门 |
| 判据内核 | Python `ast` / 静态分析 | 签名表、字段键、跨模块 import、结构体检、重复定义检测 |
| 后端 / 事件流 | FastAPI + SSE + SQLite | 本地服务、实时事件、调用账本与覆盖账本 |
| 前端 | Vue 3 + Vite | 工作台界面（蓝图 / 事件 / 报告） |
| 桌面壳 | Electron（可选） | `start.bat` 一键起后端 + 桌面窗口 |
| 验收 | pytest + 真实 HTTP 探针 | 真起服务真发请求，判状态码与 JSON 字段 |
| 模型接入 | 远端模型为主 + 本地 Ollama 兜底 | 写作档位、失败分类、截断放大重试 |
| 工程保障 | 145 项自检脚本 + 上传前扫描 | 每修一个真 bug 补一条断言；密钥/隐私上传前体检 |

## 架构

```
  需求文档 / 一句话目标
        │
        ▼
  ┌─────────────────────────────────────────────┐
  │ 编排层  blueprint → slicer → contract       │  拆能力、排依赖、定考卷
  └───────────────────┬─────────────────────────┘
                      ▼
  ┌─────────────────────────────────────────────┐
  │ 作者层  agent / author / linkfix            │  远端写码、本地只做确定性修补
  └───────────────────┬─────────────────────────┘
                      ▼
  ┌─────────────────────────────────────────────┐
  │ 判据层  gates / props / probe / archrules   │  静态闸门 → 单元判据 → 集成冒烟 → HTTP 探针
  └───────────────────┬─────────────────────────┘
                      ▼
  ┌─────────────────────────────────────────────┐
  │ 账本层  coverage / progress / remote_usage  │  观测、回归留痕、花费、交付报告
  └─────────────────────────────────────────────┘
```

关键约定：**考卷（契约）合成后缓存复用**，同一片重跑仍是同一份题；
**观测如实写回**，探针回归就降级进派单队列，不粉饰覆盖数字；
**引擎只路由不代写业务代码**，修复片同样走契约→作者→探针的完整链路。

## 核心机制

- **契约驱动**：能力先翻成可机判的函数签名 + 示例，再让模型写实现；没过判据的代码不落盘。
- **四层证据**：单函数判据 → 跨模块接线冒烟 → 业务流不变量 → 能力上限台账，逐层收窄"我以为它对了"。
- **真实探针**：HTTP 能力真起服务真发请求，包含 404 / 422 / 并发 / 跨进程回读，不靠 mock 自证。
- **自检即文档**：145 个自检脚本，每个真实 bug 都留一条断言；改语义必须同轮改断言。
- **断点与预算**：append-only 覆盖账本 + 模块进度 + `--max-cny` 硬停机线，中断可续跑。
- **三种模式**：夜班（远端主力）/ 开发者模式（人类全程参与）/ 只读分析（只确认结构）。

## 快速开始

```bash
# 桌面版（Windows，后端 + Electron 窗口）
start.bat

# 命令行：先小预算试水
python prototype/cli.py night --repo <目标仓库> --goal-file <需求文档.md> --max-cny 0.2

# 全量自检
python prototype/checks/run_all.py
```

- 交互式 API / 前端：启动后见本地服务输出
- 长需求走 `--goal-file`（全自主模式）；`--goal` 与 `--requirement-file` 互斥
- 启动前务必设 `--max-cny`（不设上限会持续烧钱）
- 环境自检、模型接入与 FAQ 见 `docs/`

## 隐私与安全

- API Key 只存本地 `prototype/data/settings.json`（已 `.gitignore`），仓库里只有模板。
- 运行期产物不入库：`_logs/`、`projects/`、`.sixcoder/`、`*.db`、会话记忆与本地交接文档全部忽略。
- 推送前跑 `python tools\preupload_scan.py`：扫密钥、隐私与不该入库的路径，输出打掩码。
- 铁律：密钥一旦推到公开仓库就等于已泄露 —— 立即在服务商侧轮换，再处理历史。
