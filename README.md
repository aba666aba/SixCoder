## 一、先认识几个词

看不懂代码的人最容易被这几个词挡住。先花 3 分钟看完，后面就顺了。

| 词 | 大白话解释 |
|---|---|
| **命令提示符 / 终端 / cmd** | 一个黑底白字的窗口，你在里面「打字命令」让电脑干活。按 `Win + R`，输入 `cmd`，回车就打开。**它不是编程，就是打字下指令** |
| **`cd`** | 「切换文件夹」。`cd /d E:\SixCoder` = 进入 E 盘的 SixCoder 文件夹 |
| **路径** | 文件在电脑里的地址，例如 `E:\SixCoder\README.md` |
| **Python** | 一种编程语言，也是运行 SixCoder 的「发动机」。**装一次就行** |
| **Node.js / npm** | 另一套工具，专门用来构建「界面」。也是**装一次就行** |
| **API Key** | 一串以 `sk-` 开头的密码，相当于「AI 服务的会员卡」。**不能给别人**，别人拿了会花你的钱 |
| **模型 / 远端** | 真正干活写代码的 AI（DeepSeek）。它在你电脑之外，所以要联网 |
| **需求文档** | 你用中文写的一份「我想要什么」的说明书。**SixCoder 全靠它干活** |
| **能力（cap）** | SixCoder 把你的需求拆成一条条「可以被打勾的检查项」，例如「学生借书后库存减 1」。每一条叫一个「能力」 |
| **判据 / 探针** | 检查「这个能力到底做没做对」的题目。探针 = 真的把服务跑起来发一次请求，看返回对不对 |
| **夜班** | 让 SixCoder 整夜自己干活、自己检查、自己修的模式。你睡觉，它上班 |
| **预算** | 允许它最多花多少钱。**默认没上限**，所以第一次用一定要设（见第六节第 3 步） |

> 记住一句就够：**你只管写清楚「要什么」，剩下的它自己折腾；你负责看最后那份报告。**

## 二、它到底是什么

一句话：**你把中文需求写进一个文件，它就能给你生成一整个能跑的项目，并附一份诚实的报告。**

它会做四件事：

1. **拆** —— 把你的需求拆成 30～100 条「能力」（可检查的小目标）
2. **写** —— 调用 AI 模型（DeepSeek）来写代码
3. **查** —— 把自己的成果**真跑起来**、真发 HTTP 请求，逐条检查
4. **修** —— 没过就改，改完再查；卡住了会叫另外两个 AI 来商量（你用三把 key 的时候）

它**不保证**代码完美，但保证**报告不说谎**：

- 过了什么，写「通过」
- 没过什么，写「没过 + 为什么 + 哪一步的请求返回了啥」
- 测不了的，写「测不了」

## 三、开始前：装好三样东西

### 3.1 检查你有没有 Python

1. 按 `Win + R` → 输入 `cmd` → 回车（打开黑色窗口）
2. 输入下面这行，按回车：

```
python -V
```

**你会看到**：类似 `Python 3.12.4`

- ✅ 看到 `Python 3.10` 以上 → 继续
- ❌ 提示「不是内部或外部命令」→ 去 https://www.python.org/downloads/ 下 3.12，**安装时第一屏底部一定要勾上 `Add python.exe to PATH`**，装完重启电脑，再试一次

### 3.2 检查你有没有 Node.js

同样在那个黑窗口里输入：

```
node -v
```

**你会看到**：类似 `v20.11.0`

- ✅ 看到 `v18` 以上 → 继续
- ❌ 报错 → 去 https://nodejs.org/ 下「LTS」版，双击安装（一路下一步即可），装完重启电脑

### 3.3 准备一个 DeepSeek 的 API Key

1. 打开 https://platform.deepseek.com/ 注册并登录
2. 左侧点「API keys」→「创建 API key」
3. 复制那串 `sk-` 开头的字符，**先粘到记事本里存好**（网页关掉后就看不到了）
4. 左侧「充值」，充 50 元就够跑很久了

## 四、安装 SixCoder

### 第 1 步：把文件夹放到合适的位置

把整个 `SixCoder` 文件夹放到**路径里没有中文、没有空格**的地方：

```
E:\SixCoder                  ✅ 正确
D:\我的项目\SixCoder          ❌ 有中文，可能出错
E:\Program Files\SixCoder    ❌ 有空格，可能出错
```

> 为什么：有些工具遇到中文/空格路径会报莫名其妙的错，新手很难排查，干脆避开。

### 第 2 步：安装 Python 依赖

1. 打开 `cmd`（`Win + R` → `cmd` → 回车）
2. 复制这一行，回车（进入引擎目录）：

```
cd /d E:\SixCoder\prototype
```

3. 再复制这一行，回车（安装依赖）：

```
python -m pip install -r requirements.txt
```

**你会看到**：屏幕滚一堆 `Downloading...`，最后出现

```
Successfully installed fastapi-... uvicorn-... pydantic-...
```

- ✅ 看到 `Successfully installed` → 继续
- ❌ 看到红色 `error` → 把最后 10 行复制下来再排错
- ⏳ 这一步 1～3 分钟，网速慢会更久，**别关窗口**

### 第 3 步：启动界面

回到 `E:\SixCoder` 文件夹，**双击 `start.bat`**。

**你可能会看到**：一个黑色窗口 + 自动安装界面依赖的文字

```
 [1/4] 检查 Python ...
 [2/4] 首次运行：安装前端依赖（npm install，约 1 分钟）…
 [3/4] 构建前端 bundle（npm run build）…
 [4/4] 首次运行：安装 Electron（可能需要几分钟）…
```

第一次会比较久（**5～10 分钟，别关**）。完成后会弹出一个白色窗口 —— 这就是工作台。

- ✅ 弹出窗口 → 安装完成，跳到第五节
- ❌ 窗口一闪就没了 → 见第十节报错对照表第 1 条
- 💡 没弹窗但黑窗口说启动成功：打开浏览器访问 http://127.0.0.1:8760

## 五、填 API Key

> 这是**最容易出错的一步**，一步一步来。

### 方式 A：在界面里填（推荐）

1. 窗口右上角找到「**远端**」按钮，点它 → 展开厂商列表
2. 点「**DeepSeek**」那张卡片（整张卡片都能点）
3. 进入「key 列表」→ 点「**＋ 新增 key**」
4. 表单里填三样：
   - **用途**：下拉选「**写作者**」（这是干活的那把 key）
   - **名字**：随便写，例如「主账号」
   - **API key**：粘贴你的 `sk-...`（注意前后不要带空格）
5. 点「**保存这个 key**」

**你会看到**：卡片上显示「已配置」+ 一串掩码（例如 `sk-abc…1234`），这就成功了。

> 💡 如果你有两三个不同的 DeepSeek 账号，可以再「＋ 新增 key」，用途分别选「审核者 1 / 审核者 2」。
> 好处：AI 卡住时会有另外两个 AI 独立投票决定怎么改，不容易钻牛角尖、也不容易白花钱。

### 方式 B：命令行填（更快）

在 `cmd` 里：

```
cd /d E:\SixCoder\prototype
python tools\set_key.py sk-把你的完整key粘在这里
```

**你会看到**：

```
新 key：sk-abc…1234（35 字符）
正在用新 key 发一次最小请求（max_tokens=1）…
✓ HTTP 200，usage={...}
✓ 已写入 3 处：remote.api_key, providers[0].api_key, providers[0].keys[k1].api_key
  备份：settings.json.bak-20261119-012345
✓ 复验通过
```

- ✅ 看到「复验通过」= key 可用，已写入
- ❌ 看到「格式不对 / 长度不对 / 打不通」= key 复制错了，重新复制

**只想验证、不写入**：

```
python tools\set_key.py --check
```

## 六、准备你的第一个项目

### 第 1 步：建一个空文件夹

例如 `E:\MyProject`（同样：不要中文、不要空格）。

### 第 2 步：在里面放一份需求文档

**文件名必须是 `REQUIREMENTS.md`**（一个字都不能差）。

用记事本或 VS Code 新建这个文件，写中文需求。**写得越具体，效果越好**：

**❌ 太模糊**

```
做一个图书管理系统
```

**✅ 具体（推荐直接抄这个格式）**

```
# 图书借阅系统

## 有哪几种人
- 管理员：能登记新书、下架旧书、查看所有借阅记录
- 学生：能借书、还书，能查自己借了几本

## 借书规则
- 每本书有库存数量，借出一本库存减 1，还回来加 1
- 库存为 0 时，借书要失败，并提示「这本书暂时借完了」
- 每个学生最多同时借 3 本，超过要失败并提示「你已借满 3 本」
- 借书后 30 天内必须还，超过显示「逾期 X 天」

## 管理员能看到的统计
- 借阅次数最多的 10 本书（书名 + 次数）
- 当前逾期未还的名单（学生名 + 书名 + 逾期天数）
```

> 为什么这么写：SixCoder 会把每一条**能判断对错**的描述变成一条检查项。
> 你写「借满 3 本就失败」，它就会真的去试「借第 4 本」并检查是否报错。

### 第 3 步（强烈建议）：先设一个花钱上限

默认**没有上限**，第一次用很容易跑飞。手动设一下，只要 30 秒：

1. 在 `E:\MyProject` 里新建文件夹，名字就叫 `.sixcoder`（前面有个英文句点，别漏）
2. 进入 `.sixcoder`，新建文件 `budget.json`
3. 里面只写这两行：

```json
{ "system_budget_cny": 100 }
```

意思是：总花费到 **105 元**（100 × 1.05）就自动收工。

## 七、让它开始干活

### 7.1 最省心的方式：跑一夜

**双击 `E:\SixCoder\START_NIGHT.bat`**，然后就可以去睡觉了。

**你会看到**：一个黑色窗口一闪（正常，它在后台跑），之后所有输出都写进日志。

### 7.2 白天想盯着跑（能看到实时输出）

```
cd /d E:\SixCoder\prototype
python cli.py night --repo E:\MyProject --goal-file E:\MyProject\REQUIREMENTS.md
```

- `--repo` 后面 = 你的项目文件夹
- `--goal-file` 后面 = 你的需求文档
- 这个窗口**不要关**，关了就停了

### 7.3 只想看现状、完全不花钱

```
cd /d E:\SixCoder\prototype
python cli.py full --repo E:\MyProject
```

它只做检查、写报告，**不调用 AI**，一分钱不花。适合先看看需求被拆成了哪些能力。

### 7.4 怎么停

- 双击 `E:\SixCoder\STOP_NIGHT.bat`
- 或者按 `Ctrl + C`（7.2 那种前台窗口）

## 八、看不懂界面？这里是导览

窗口主要就几块，记住三块就够用：

| 位置 | 是什么 | 你要做什么 |

## 九、跑完怎么看结果

打开你的项目文件夹 `E:\MyProject`，会多出这些东西：

| 文件/文件夹 | 是什么 | 建议怎么看 |
|---|---|---|
| **`DELIVERY.md`** | **交付报告**（最重要） | 从头读：做了什么、没做什么、花了多少钱 |
| `.sixcoder\errors_report.md` | 错误清单（按严重程度排序） | 只看 P0 / P1 就够 |
| 你的代码 | 生成出来的项目 | 想跑起来看效果，看里面有没有 README |
| `.sixcoder\` 其他文件 | 引擎的记账本（蓝图/预算/日志） | 不用管，**别删** |
| `E:\SixCoder\_logs\*.log` | 引擎运行日志 | 出问题时把最新的发给开发者 |

**报告怎么读（三分钟版）**：

1. 先看开头一句：「XX 条能力，通过 54 条」——这决定整体进度
2. 再看「没通过的」列表，每条都写了具体原因，例如
   `cap.borrow.stock  失败：POST /api/books/1/borrow/ 期望 400，实际 200（库存为 0 也能借）`
   意思是：**需求说「库存为 0 要拒绝」，但程序居然允许借**
3. 最后看「本次花费」：¥ 多少、多少 token

## 十、常见报错对照表

| 你看到的 | 原因 | 怎么办 |
|---|---|---|
| 双击 `start.bat` 一闪就没 | 有错误，窗口关太快看不清 | 打开 `cmd`，输入 `cd /d E:\SixCoder` 回车，再输入 `start.bat` 回车，错误会留在屏幕上 |
| `'python' 不是内部或外部命令` | 装 Python 时没勾 PATH | 重装 Python 并勾 `Add python.exe to PATH`；或用完整路径 `"D:\Python\python.exe"` 代替 `python` |
| `'npm' 不是内部或外部命令` | 没装 Node.js | 装 nodejs.org 的 LTS 版，重启电脑 |
| `Could not find a version that satisfies...` | 网络问题或 Python 版本太低 | 换网络重试；确认 `python -V` ≥ 3.10 |
| 界面显示「远端未配置」 | Key 没填成功 | 按第五节重填；用 `python tools\set_key.py --check` 验证 |
| `HTTP 401` / `Authentication Fails` | Key 错了/过期/多复制了空格 | 重新复制整串 key（`sk-` 开头共 35 个字符），再写入一次 |
| `HTTP 402` / `Insufficient Balance` | 余额不足 | 去 platform.deepseek.com 充值 |
| 跑了一夜，通过数没涨 | 多半是自检题目本身互相矛盾 | 看 `DELIVERY.md` 的「没通过原因」；新版会自动叫 3 个 AI 协商改题目；还不行把 `_logs` 最新日志发开发者 |
| 关掉窗口后进程还在 | 夜班是独立进程，关窗口不停 | 双击 `STOP_NIGHT.bat` 停 |
| 提示「已有看门狗实例在跑」 | 之前启动的还没退出 | 正常防重复启动；要重启先 `STOP_NIGHT.bat` |
| 项目里的代码跑不起来 | AI 写的不一定对 | 看 `errors_report.md`；也可以再跑一夜让它继续修 |

## 十一、换项目 / 卸载

### 换项目（同一个引擎跑多个项目）

引擎和项目是**分开的**，不用改代码：

1. 建新文件夹，例如 `E:\Project2`，放新的 `REQUIREMENTS.md`
2. 启动时指定：

```
cd /d E:\SixCoder\prototype
python cli.py night --repo E:\Project2 --goal-file E:\Project2\REQUIREMENTS.md
```

或者改 `E:\SixCoder\_logs\engine.json`（只写这一行）：

```json
{ "repo": "E:\\Project2" }
```

以后不带 `--repo` 也知道去哪儿。

### 卸载

1. 双击 `STOP_NIGHT.bat` 停止所有进程
2. 直接删掉 `E:\SixCoder` 文件夹
3. 想彻底清干净：再删掉你项目里的 `.sixcoder` 文件夹

（API Key 只存在 `E:\SixCoder\prototype\data\settings.json`，删文件夹即清掉。）

- 依赖锁定：`requirements.txt` / `requirements-dev.txt`
- 上传前隐私体检：`python tools\preupload_scan.py`
