# SixCoder 使用说明书

> 这份说明写给**要做出东西的人**——不一定会写代码，也可能是个老手。
> 每一步都写了：**要做什么 → 怎么做 → 做完应该看到什么 → 出错了怎么办**。

---

## 零、这个产品是干什么的（先看这个，1 分钟）

**SixCoder 是一条流水线，三个模式就是三个阶段。**

它解决的是一件事：**把「从零到一个能用的东西」这段时间压缩掉**。不同类型的人走不同长度的阶段：

| 你是谁 | 你要什么 | 用哪个模式 | 得到什么 |
|---|---|---|---|
| **不写代码的人** | 一个能跑的小工具、小网页 | **造物模式** | 说清要什么 → 一夜跑完 → 早上拿到能用成品 + 交付报告 |
| **程序员** | 把原型继续做成产品 | **造物 → 精修 → 审阅** | 夜里出原型，白天在软件里精修，交付前审计出文档 |

### 三个阶段各自负责什么

**① 造物模式 —— 从 0 到 1**

你只描述想要什么，不关心实现。系统把它拆成可检查的小目标，整夜自己写、自己跑、自己改，
早上给你一份**不说谎的交付报告**。

对普通人：做个小工具、小网页，**这一个模式就够了**。
对程序员：大型项目用它**生成初始原型**，省掉"从头搭骨架"那几天。

**② 精修模式 —— 在软件里把原型做下去**

打开代码就有编辑器，选中一段就能让 AI 帮忙：**解释 / 改写 / 补测试**。
还能直接运行和调试。关键节点（写文件、提交、推送）**必须你点头**，不会自作主张。

这是程序员用得最多的阶段，也是原型能不能长成产品的地方。

**③ 审阅模式 —— 只读不写，审计 + 出文档**

接手一个东西之前，先搞清楚它**到底靠不靠谱**：

- **零 token 审计**：架构违规、空壳测试、临时方案、TODO 一次列清（不花钱）
- **按代码生成文档**：模块说明、架构概览、**交接单**（接手前必须知道什么）

不写一个字节，也不会碰 git。

### 一句话记住

> **造物出原型，精修做产品，审阅保质量。**
> 普通人用第一个就够；程序员三个连着用。

### 它保证什么、不保证什么

**保证**：报告不说谎。过了写"通过"，没过写"没过 + 为什么"，测不了写"测不了"。

**不保证**：代码业务正确。机械判据拦得住"不符合契约 / 模块接不上 / 读写不一致"，
**拦不住需求理解错了**。边界、性能、安全仍需人看——这也是为什么有阶段②和③。

## 一、先认识几个词

看不懂代码的人最容易被这几个词挡住。先花 3 分钟看完，后面就顺了。

| 词 | 大白话解释 |
|---|---|
| **命令提示符 / 终端 / cmd** | 一个黑底白字的窗口，你在里面「打字命令」让电脑干活。按 `Win + R`，输入 `cmd`，回车就打开。**它不是编程，就是打字下指令** |
| **`cd`** | 「切换文件夹」。`cd /d E:\SixCoder` = 进入 E 盘的 SixCoder 文件夹 |
| **路径** | 文件在电脑里的地址，例如 `E:\SixCoder\README.md` |
| **Python** | 一种编程语言，也是运行 SixCoder 的「发动机」。**装一次就行** |
| **Node.js / npm** | 另一套工具，专门用来构建「界面」。也是**装一次就行** |
| **API Key** | 一串以 `sk-` 开头的密码，相当于「AI 服务的会员卡」。**不能给别人**，别人拿了会花你的钱 |
| **模型 / 远端** | 真正干活写代码的 AI（DeepSeek）。它在你电脑之外，所以要联网 |
| **Ollama** | 一个「在自己电脑上跑 AI」的小工具，**可选**。装了能让它顺手帮你改几行小地方（省点钱）；不装照样能跑，只是没有这层便利 |
| **需求文档** | 你用中文写的一份「我想要什么」的说明书。**SixCoder 全靠它干活** |
| **能力（cap）** | SixCoder 把你的需求拆成一条条「可以被打勾的检查项」，例如「学生借书后库存减 1」。每一条叫一个「能力」 |
| **判据 / 探针** | 检查「这个能力到底做没做对」的题目。探针 = 真的把服务跑起来发一次请求，看返回对不对 |
| **夜班** | 让 SixCoder 整夜自己干活、自己检查、自己修的模式。你睡觉，它上班 |
| **预算** | 允许它最多花多少钱。**默认没上限**，所以第一次用一定要设（见第六节第 3 步） |

> 记住一句就够：**你只管写清楚「要什么」，剩下的它自己折腾；你负责看最后那份报告。**

## 二、造物模式是怎么干活的

一句话：**你把中文需求写进一个文件，它就能给你生成一整个能跑的项目，并附一份诚实的报告。**

它会做四件事：

1. **拆** —— 把你的需求拆成 30～100 条「能力」（可检查的小目标）
2. **写** —— 调用 AI 模型（DeepSeek / GLM / 任意 OpenAI 兼容端点）来写代码
3. **查** —— 把自己的成果**真跑起来**、真发 HTTP 请求，逐条检查
4. **修** —— 没过就改，改完再查；卡住了会叫另外两个 AI 来商量（你用三把 key 的时候）

它**不保证**代码完美，但保证**报告不说谎**：

- 过了什么，写「通过」
- 没过什么，写「没过 + 为什么 + 哪一步的请求返回了啥」
- 测不了的，写「测不了」

> 💡 报告开头现在会多一节「**这份报告能证明什么、不能证明什么**」，
> 并**当场跑一次独立验收**把结果并排印出来。两边不一致时，以独立验收为准。

## 三、开始前：只需要一样东西

> 安装版已经把 Python 运行时、依赖、界面全部打进去了，**你不需要装 Python，也不需要装 Node.js**。

### 3.1 准备一个 DeepSeek 的 API Key

1. 打开 https://platform.deepseek.com/ 注册并登录
2. 左侧点「API keys」→「创建 API key」
3. 复制那串 `sk-` 开头的字符，**先粘到记事本里存好**（网页关掉后就看不到了）
4. 左侧「充值」，充 50 元就够跑很久了

### 3.4 本地 Ollama（**可选**，不装也能跑）

**先说结论：不装完全可以。** 只要上面那个 DeepSeek Key 是通的，写代码、检查、修错全都由远端完成，本机不需要跑任何 AI 模型。

装了它多出三样好处（都是「锦上添花」，不是必需）：

| 用途 | 具体是什么 | 不装会怎样 |
|---|---|---|
| **小改动委托** | 远端回一句「把第 3 行的变量名改成 xxx」，这种小活让它在本机改，省一次远端往返（每个文件最多 3 处） | 交给远端重写一次，多花一点点钱 |
| **换模型再试** | 撞墙时换一个本机更强/更专精代码的模型再试一把 | 少一种打法，问题交给三方协商解决 |
| **完全离线兜底** | 远端全挂了还能用 `--no-remote` 硬跑 | 只能用远端 |

**想装就三步**：

```bat
rem 1) 到 https://ollama.com/download 下载安装（Windows 版，双击装完即可）
rem 2) 拉一个写代码的模型（约 4.7GB，一次就够）
ollama pull qwen2.5-coder:7b

rem 3) 确认装好了
ollama list
```

**你会看到**：`ollama list` 里出现 `qwen2.5-coder:7b` 这一行，就说明好了。

> 💡 引擎会自动挑本机**最强的那个 7B 以上写代码模型**用；只有 3B 小模型时它宁可不换（实测 3B 交不出能解析的代码，换了等于浪费一轮钱）。所以**要么装 7B 以上，要么就别装**，装个 3B 反而没意义。
>
> 💡 不装 / 没启动 Ollama 时引擎不会报错：它查不到本地模型就自动跳过上面三件事，远端照常干活。

## 四、安装 SixCoder

### 第 1 步：双击安装包

拿到 `SixCoder-Setup-1.1.0.exe`，**双击它**。

- 装到当前用户目录（`%LOCALAPPDATA%\Programs\SixCoder`），**不会弹管理员权限**
- 装完桌面和开始菜单会有 `SixCoder` 图标
- 只有可选组件页会问你：要不要顺便装「本地模型」（Ollama + qwen2.5-coder:7b）。**默认都不勾，直接下一步就行** —— 不装也能跑完整流程，之后想装随时从开始菜单 `SixCoder 环境准备` 补

### 第 2 步：以后更新也是双击新安装包

新版本直接双击覆盖安装即可：

- 装到同一个位置，**旧版本自动被替换**
- **本地数据保留**：夜班日志、任务历史、已保存的 Key 都在 `%LOCALAPPDATA%\SixCoder`，不在安装目录里，覆盖安装不会碰
- 你的项目仓库（源码、`.git` 历史、`.sixcoder`）更不会被碰
- 更新前如果界面开着或夜班在跑，安装程序会先把它停掉（否则文件被占用没法替换）；装完重新打开界面、需要的话点一次「开始夜班」即可

### 第 3 步：启动

双击桌面 `SixCoder`。第一次启动约 5～10 秒（在起后端服务），然后出现工作台窗口。

- ✅ 出现窗口 → 跳到第五节
- ❌ 窗口里显示「后端启动失败」→ 看第十节的排错表
- ❌ 窗口一闪就没了 / 双击完全没反应（任务管理器里有进程但没窗口）→ 见第十节报错对照表前两条
- 💡 没弹窗但黑窗口说启动成功：打开浏览器访问 http://127.0.0.1:8760

## 五、填 API Key

> 这是**最容易出错的一步**，一步一步来。

### 方式 A：在界面里填（推荐）

1. 窗口右上角找到「**远端**」按钮，点它 → 展开厂商列表
2. 点「**DeepSeek**」那张卡片（整张卡片都能点）
3. 进入「key 列表」→ 点「**＋ 新增 key**」
4. 表单里填三样：
   - **用途**：下拉选「**写作者**」（这是干活的那把 key）
   - **名字**：随便写，例如「主账号」
   - **API key**：粘贴你的 `sk-...`（注意前后不要带空格）
5. 点「**保存这个 key**」

**你会看到**：卡片上显示「已配置」+ 一串掩码（例如 `sk-abc…1234`），这就成功了。

> 💡 如果你有两三个不同的 DeepSeek 账号，可以再「＋ 新增 key」，用途分别选「审核者 1 / 审核者 2」。
> 好处：AI 卡住时会有另外两个 AI 独立投票决定怎么改，不容易钻牛角尖、也不容易白花钱。

### 方式 B：命令行填（更快）

在 `cmd` 里：

```
cd /d E:\SixCoder\prototype
python tools\set_key.py sk-把你的完整key粘在这里
```

**你会看到**：

```
新 key：sk-abc…1234（35 字符）
正在用新 key 发一次最小请求（max_tokens=1）…
✓ HTTP 200，usage={...}
✓ 已写入 3 处：remote.api_key, providers[0].api_key, providers[0].keys[k1].api_key
  备份：settings.json.bak-20261119-012345
✓ 复验通过
```

- ✅ 看到「复验通过」= key 可用，已写入
- ❌ 看到「格式不对 / 长度不对 / 打不通」= key 复制错了，重新复制

**只想验证、不写入**：

```
python tools\set_key.py --check
```

## 六、准备你的第一个项目

### 第 1 步：建一个空文件夹

例如 `E:\MyProject`（同样：不要中文、不要空格）。

### 第 2 步：在里面放一份需求文档

**文件名必须是 `REQUIREMENTS.md`**（一个字都不能差）。

用记事本或 VS Code 新建这个文件，写中文需求。**写得越具体，效果越好**：

**❌ 太模糊**

```
做一个图书管理系统
```

**✅ 具体（推荐直接抄这个格式）**

```
# 图书借阅系统

## 有哪几种人
- 管理员：能登记新书、下架旧书、查看所有借阅记录
- 学生：能借书、还书，能查自己借了几本

## 借书规则
- 每本书有库存数量，借出一本库存减 1，还回来加 1
- 库存为 0 时，借书要失败，并提示「这本书暂时借完了」
- 每个学生最多同时借 3 本，超过要失败并提示「你已借满 3 本」
- 借书后 30 天内必须还，超过显示「逾期 X 天」

## 管理员能看到的统计
- 借阅次数最多的 10 本书（书名 + 次数）
- 当前逾期未还的名单（学生名 + 书名 + 逾期天数）
```

> 为什么这么写：SixCoder 会把每一条**能判断对错**的描述变成一条检查项。
> 你写「借满 3 本就失败」，它就会真的去试「借第 4 本」并检查是否报错。

### 第 3 步（强烈建议）：先设一个花钱上限

默认**没有上限**，第一次用很容易跑飞。手动设一下，只要 30 秒：

1. 在 `E:\MyProject` 里新建文件夹，名字就叫 `.sixcoder`（前面有个英文句点，别漏）
2. 进入 `.sixcoder`，新建文件 `budget.json`
3. 里面只写这两行：

```json
{ "system_budget_cny": 100 }
```

意思是：总花费到 **105 元**（100 × 1.05）就自动收工。

## 七、让它开始干活

### 7.1 最省心的方式：跑一夜

1. 打开 `SixCoder`
2. 左上角选你的**项目文件夹**
3. 中间填需求（或切「全自主模式」写一句话目标）
4. 点 **「开始夜班」**

点完就可以关窗口去睡觉了 —— 夜班跑在**独立进程 + 看门狗**里，关界面不中断、崩了自动重启。

**早上回来看**：重新打开界面，同一块面板会显示进度、花费、停机线和交付报告。

### 7.2 白天想盯着跑

界面里点「开始夜班」时**不要**勾「后台长跑」，就是前台执行、实时刷进度。

### 7.3 只想看现状、完全不花钱

点运维行的 **「检测（零 token）」**：只跑检测器、写 `.sixcoder/errors_report.md`，**不调用 AI**，一分钱不花。适合先看看需求被拆成了哪些能力。

想让它顺手修掉检查出来的问题，点 **「检测 + 修复」**（会花 token，实测 10～15 分钟）。

### 7.4 怎么停

点运维行的 **「停止夜班」**。它会先停看门狗再停夜班进程，不会出现「杀了又自己起来」。

关掉界面**不是**停止：夜班在独立进程里继续跑，这是设计如此。

## 七点五、第二、三阶段怎么用

### 7.5 精修模式：在软件里接着改

拿到原型（或者任何时候想改代码），把顶栏模式切到 **精修模式**：

1. 左栏文件树点开一个 `.py`，中间就是编辑器
2. **选中一段代码**，右上角浮窗会出现四个动作：
   - **解释** —— 这段干什么、输入输出、关键分支、有什么风险
   - **改代码** —— 用一句话说怎么改（如「改成用正则」），给你改写后的版本
   - **补测试** —— 按正常 / 边界 / 异常三条路径生成 pytest
   - **引用** —— 看谁在调用它
3. 改完能直接 **运行 / 调试**（断点、单步、看变量）

> AI 浮窗有两个来源：**本地模型**（快、免费，适合小改）和**远端**（慢、要钱，但能读懂复杂意图）。
> 在浮窗里可以切换。
>
> 精修模式下，**写文件 / 提交 / 推送 / 上报远端 / 收尾交付**这五个节点不会自动放行，
> 会在顶栏「待审 N」里等你点头。

### 7.6 审阅模式：交付前先审计

把顶栏切到 **审阅模式**（只读，不会改任何文件）：

1. 点 **「审查」** —— 静态审查 + 改进意见
2. **零 token 审计**（不花钱）一次列清：
   - 架构违规（依赖环、层级方向）
   - 空壳测试（0 个测试函数 / `assert True`）
   - 临时方案（TODO / HACK / 临时绕过）
3. 想让它**按代码生成文档**，目前有两个入口：
   - 命令行：`python tools\hq_verify.py <项目目录>`
   - 接口：`GET /v1/audit?repo=<目录>`、`POST /v1/docs/stage3`

   生成三份：
   - `MODULES.md` —— 每个模块做什么、对外暴露什么、被谁依赖
   - `ARCHITECTURE.md` —— 依赖方向 + 有没有环 + 架构违规
   - `HANDOVER.md` —— **交接单**：测试成色、已知问题、没测的边界、从哪开始读

> 💡 `HANDOVER.md` 最该看。它专门回答"接手之前你必须先知道什么"——
> 比如"这份测试其实是空壳""这几个边界没人测过"。

## 八、看不懂界面？这里是导览

窗口主要就几块，记住三块就够用：

| 位置 | 是什么 | 你要做什么 |
|---|---|---|

## 九、跑完怎么看结果

打开你的项目文件夹 `E:\MyProject`，会多出这些东西：

| 文件/文件夹 | 是什么 | 建议怎么看 |

   意思是：**需求说「库存为 0 要拒绝」，但程序居然允许借**
3. 最后看「本次花费」：¥ 多少、多少 token

## 十、常见报错对照表

| 你看到的 | 原因 | 怎么办 |
|---|---|---|
| 双击安装包没反应 / 装到一半失败 | 旧版本或它的进程还占着文件 | 先在任务管理器结束 `SixCoder.exe`，再双击安装包重装一次（覆盖安装会保留你的数据） |
| 双击图标**完全没反应**：任务管理器里 `SixCoder.exe` 在，但没窗口、没提示、日志也不涨 | 环境变量 `ELECTRON_RUN_AS_NODE` 被设成了 `1`（常见于装过开发工具 / CI 环境的机器）：它会让程序以纯 Node 模式启动，**不加载界面**，所以永远出不来窗口 | 命令行执行 `setx ELECTRON_RUN_AS_NODE ""`，重新打开程序即可。确认方法：`echo %ELECTRON_RUN_AS_NODE%` 不该输出 `1` |
| 安装时弹出「Windows 已保护你的电脑」 | 安装包没有代码签名（个人版没买证书） | 点「更多信息」→「仍要运行」 |
| 打开后显示「后端启动失败」 | 端口 8760 被占用，或安装目录被安全软件锁住 | 关掉其它可能占用 8760 的程序；把安装目录加进杀软白名单后重开 |
| 界面显示「远端未配置」 | Key 没填成功 | 在「设置 → 远端」重填；用 `python tools\set_key.py --check` 验证 |
| `HTTP 401` / `Authentication Fails` | Key 错了/过期/多复制了空格 | 重新复制整串 key（`sk-` 开头共 35 个字符），再写入一次 |
| `HTTP 402` / `Insufficient Balance` | 余额不足 | 去 platform.deepseek.com 充值 |
| 跑了一夜，通过数没涨 | 多半是自检题目本身互相矛盾 | 看 `DELIVERY.md` 的「没通过原因」；新版会自动叫 3 个 AI 协商改题目；还不行把日志发开发者 |
| 关掉窗口后进程还在 | 夜班是独立进程，关窗口不停（设计如此） | 在界面点「停止夜班」 |
| 提示「已有夜班在跑」 | 之前启动的还没退出 | 正常防重复启动；要重启先点「停止夜班」 |
| 项目里的代码跑不起来 | AI 写的不一定对 | 看 `errors_report.md`；点「检测 + 修复」继续修 |

## 十一、换项目 / 卸载

### 换项目（同一个引擎跑多个项目）

引擎和项目是**分开的**，不用改代码：界面左上角换一个项目文件夹就行。

### 卸载

打开 **设置 → 应用 → 已安装的应用**，找到 `SixCoder` → 卸载。

卸载时会问你一句：**是否保留本地运行数据**（夜班日志、任务历史、已保存的 Key），**默认勾选保留**。

- 勾选（默认）：只删程序本体，重装后能接着上次的进度
- 取消勾选：连本地数据一起清掉，彻底不留残留

**无论勾不勾，你的项目仓库都不会被删** —— 源码、`.git` 提交历史、`.sixcoder` 账本都不在安装目录里，卸载脚本连它的路径都不碰。

（API Key 只存在 `E:\SixCoder\prototype\data\settings.json`，删文件夹即清掉。）

## 十二、给会写代码的人

- 全量自检：`cd prototype && python checks\run_all.py`（227 项；每修一个真 bug 必须补一条断言）
